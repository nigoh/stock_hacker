CLI を覚えなくていい。意図を言えば、手順が走る。

Skills は stock_hacker の一番上の層です。--period や --cost-bps を 思い出す代わりに /analyze 7203 と書けば、スキルが 読むべきナレッジ・叩くべき CLI・通すべき検証・書くべき免責まで含んだ手順を実行します。 コマンドは薄いラッパーで、手順の正は .claude/skills/*/SKILL.md にあります。

Skills

スキル 18 — どんなときに、どれを使うか

スキルは「この依頼が来たら、この順で、この禁止事項を守って作業する」という手順書です。 各スキルの description には使う場面と使わない場面が明記されていて、 Claude はそれを見て自動で選びます（/… で明示的に呼ぶこともできます）。

analyze-stock
特定1銘柄の分析・評価・調査を頼まれたとき。テクニカル・ファンダメンタルズ・リスク指標・セクター文脈を統合し、ナレッジベースを枠組みとして reports/ に日本語レポートを生成する。 コマンド: /analyze ／ 複数銘柄の比較・スクリーニングには使わない。
compare-stocks
指定された2銘柄以上の相対比較。期首=100 の相対パフォーマンス、年率リターン/ボラ、シャープ、最大DD、日次リターン相関行列を取得し、ポートフォリオ理論の文書で解釈する。 コマンド: /compare ／ 1銘柄の深掘り・条件抽出には使わない。
screen-market
「RSI30以下の銘柄は？」「割安な銘柄を探して」のように、条件に合う銘柄を複数抽出したいとき。結果は結論ではなく仮説の候補リストとして解釈・報告する。 コマンド: /screen ／ 指定済み銘柄の比較には使わない。
earnings-analysis
業績推移・決算の時系列深掘り。売上・利益・マージン・ROE の推移や CAGR、法定開示（EDINET）の確認まで。 コマンド: /earnings ／ 株価・テクニカルを含む総合分析には使わない。
backtest-strategy
ルールベース売買戦略の過去データ検証。数字を出すだけでは完了ではなく、t統計量・多重検定補正・ルックアヘッド/生存者バイアス・取引コスト・IS/OOS 分割のチェックを必ず通す。 コマンド: /backtest ／ 単発の銘柄分析には使わない。
market-review
個別銘柄ではなく市場全体（指数・為替・金利・セクター動向）の把握。事実（数値・騰落）と解釈（背景・文脈）を必ず分離して書く。 コマンド: /market ／ 個別銘柄の深掘り・条件スクリーニングには使わない。
daily-brief
ウォッチリスト銘柄の定点観測。市況（^N225・1306.T・USDJPY=X・^GSPC）と各銘柄のシグナル（RSI過熱・移動平均クロス・出来高急増・52週高安接近・MACD・ボリンジャー・ADX）を検出する。 コマンド: /brief ／ 市況の詳細レビューには market-review を使う。
portfolio-review
保有銘柄 CSV の評価額・損益・セクター配分・加重β・相関・集中度（HHI）・VaR の定量評価とリスク解釈。 コマンド: /portfolio ／ 保有していない銘柄同士の比較には使わない。
dividend-income
保有銘柄の配当インカム集計。TTM 実績配当ベースの年間受取見込み・YOC・時価利回り・口座区分別の税引後手取り・NISA 非課税メリットまで。 コマンド: /income ／ 高配当銘柄の抽出は screen-market の領分。
tax-view
課税口座の含み損益を税価値の観点で機械的に整理。損益通算・繰越控除・NISA が対象外である点を対比する。どの銘柄を売るかの判断はしない。 コマンド: /tax ／ 配当の税引後手取りは dividend-income。
performance-review
「これまで年率何%で回っていたか」を取引履歴 CSV から測定。入出金を調整した金額加重リターン（XIRR）・損益内訳・同じキャッシュフローをベンチマークに投じた場合の比較。 コマンド: /performance ／ 現時点のスナップショット評価は portfolio-review。
asset-planning
積立額・目標額・進捗・取り崩し・新NISA 枠の試算。ネットワーク不要・価格データ不使用で、決定論的複利＋モンテカルロのファンチャートを出し、想定リターンの根拠を問い直すところまで行う。 コマンド: /plan ／ 出力は仮定に基づく試算であり将来の予測・保証ではない。
research-journal
検証可能な仮説を後から機械的に採点できる形で journal/ に記録する。記録時点の終値を自動スナップショットし、仮説・根拠・反証条件を残す。 コマンド: /journal ／ 期日が来た仮説の検証は journal-review。
journal-review
検証期日が来た仮説の答え合わせ。ベンチマーク調整後リターンから hit/miss/mixed を機械判定し、行動ファイナンスの認知バイアスの枠組みで「外れた仮説から何を学ぶか」を振り返る。 コマンド: /journal-review ／ 判定は機械に任せ、スキルの主眼は解釈と振り返り。
overnight-forecast
翌営業日の機械予想 → 翌日の採点 → 台帳（forecasts/ledger.csv）への蓄積 → 的中率・Brier・較正の集計。短期予想の track record を継続測定したいとき。 コマンド: /overnight ／ 詳細は Forecast ページ。予想は断定でも助言でもない。
knowledge-doc
knowledge/ への文書の新規追加・更新。ケバブケースのファイル名・冒頭要約・LaTeX 数式・「〜年時点」表記といった規約と、00-index.md への索引反映・相互リンクまでを一貫して行う。 コマンド: /learn ／ 索引未反映のままだと hook がブロックする。
mape-night
MAPE-K の夜間周回（Monitor→Analyze→Plan）。予測精度と分析カバレッジを観測して改善案を作り、GitHub 計画イシューにチェックリストで掲示する。読み取り中心で安全。 コマンド: /mape-night ／ 実装は含まない（それは mape-execute）。
mape-execute
MAPE-K の Execute。計画イシューのチェック済み・未着手を1周1件だけ実装し、pytest が緑ならドラフト PR、赤なら破棄して記録する。 コマンド: /mape-execute ／ 個別銘柄の分析や新規レポート作成には使わない。
使い分けの原則

1銘柄の深掘り → analyze-stock／業績の時系列 → earnings-analysis／ 横比較 → compare-stocks／条件で絞り込む → screen-market／ 売買ルールの検証 → backtest-strategy／市場全体 → market-review／ 保有の評価 → portfolio-review／ウォッチ銘柄の定点観測 → daily-brief。

知識を足す → knowledge-doc／仮説を残す → research-journal／ 期日が来た仮説を検証 → journal-review／翌営業日予想と答え合わせ → overnight-forecast。

積立・目標・取り崩し → asset-planning／配当収入 → dividend-income／ 含み損益の税務整理 → tax-view／実績リターン（XIRR） → performance-review。 迷ったら、対象が「1銘柄か・複数か・市場全体か・自分の資産か」で切り分けるのが早い。

Subagents

サブエージェント 4 — 重い作業の委譲先

独立した文脈で長い作業を回すための専門家。定義は .claude/agents/*.md にあり、 それぞれ持てるツールが絞られています（例: risk-officer は Write / Edit を持たない＝レビューはするが直さない）。

agent · analysis

stock-analyst

個別銘柄の深掘り分析とレポート作成。テクニカル・ファンダメンタル・リスク・セクター文脈を統合し、 事実と解釈を峻別したレポートを reports/ に書く。
使わない場面: 複数銘柄の比較、戦略バックテスト、市場全体のスクリーニング。

agent · research

quant-researcher

戦略研究・バックテスト・統計的検証。人格の中核は統計的懐疑主義で、 「儲かって見える結果」をまず偶然・バイアス・過剰適合の産物として疑う（t統計量・多重検定・IS/OOS）。
使わない場面: 個別銘柄の総合分析、完成レポートのレビュー。

agent · gate

risk-officer

成果物（レポート・スクリプト・バックテスト結果）の敵対的レビュー。著者の主張を鵜呑みにせず、 数字・コード・記述の整合性を独立に検証する。ツールは読み取り系のみ。
使わない場面: 新規の分析やレポート作成そのもの。

agent · knowledge

knowledge-curator

knowledge/ の保守。索引（00-index.md）と本文の整合、重複トピックの統合、 「〜年時点」記述の陳腐化検出と更新、新規文書の追加。
使わない場面: 銘柄分析・バックテスト・レポートレビュー。

品質ゲート

重要なレポートを外部共有・意思決定に使う前は、必ず /review-report を通す。 risk-officer が検出するのは4点——統計的誤り（t統計量の欠落・多重検定の未申告・年率化の誤り）、 ルックアヘッド・バイアス（シグナルと約定の同一足、生存者バイアス、コスト仮定）、 投資助言化（断定的将来予測・売買推奨に読める記述・免責文の欠落）、 合成データの偽装（--synthetic 使用の明記なしに実データと誤認させる記述。これが最重大）。

報告は重大度順に「重大度・根拠・修正案」の形式で返り、最後に総合判定（差し戻し／条件付き可／可）が付きます。 修正はレビューの範囲外です（risk-officer は書き込み権限を持たない）。 レビューを通ったことは、投資判断の正しさを保証しません。

Hooks

hooks 3 — 規約を人の記憶ではなく仕組みで守る

「索引に載せ忘れない」「免責を書き忘れない」は、注意力ではなく自動実行に任せます。 設定は .claude/settings.json、実体は scripts/ 配下のスクリプトです。 PostToolUse フックが exit 2 を返すと、その内容が Claude に差し戻され、修正してから先へ進みます。

フックスクリプト動作
SessionStart scripts/session_start.sh 依存パッケージ（pandas / numpy / yfinance / pytest）の確認と導入、reports/・data/cache/ の作成、stocklib のインポート・スモークチェック、環境の要点とジャーナル期日サマリーをセッション文脈に注入。ネットワーク不通でもセッションを止めない（原則 exit 0）。
PostToolUse Write｜Edit scripts/check_knowledge_index.py 書き込まれたファイルが knowledge/ 配下の Markdown なのに 00-index.md から参照されていなければ exit 2 でブロックし、索引への反映を促す。--all で索引リンクの解決・文書数の一致まで含めた全体整合チェック（CI 用）も行える。
PostToolUse Write｜Edit scripts/check_report_disclaimer.py reports/ 配下の Markdown に「投資助言ではありません」または「免責」が含まれなければ exit 2 でブロックし、stocklib.report.DISCLAIMER の追記を促す。CLI 生成レポートは自動で免責が付くが、Claude が直接書いたレポートには機械的な担保がないため。
MAPE-K

夜間セルフ改善 — 読むフェーズと壊しうるフェーズを分ける

「株の解析の醸成」を主題に、予測精度（台帳の的中率・Brier、ジャーナルの hit 率）と 分析カバレッジ（ユニバースの網羅・ナレッジの鮮度）の2軸を夜間に測り、改善へ回す仕組みです。 安全性の要は、安く読んで考える工程と、実際にコードを触る工程を分離したことにあります。

/mape-night · 読み取り中心

Monitor → Analyze → Plan

リポジトリを観測し（mape/analysis_signals.py が台帳・ジャーナル・ユニバース・ナレッジを stdlib のみ・ネットワーク不使用で集計）、改善案をチェックリストにして GitHub 計画イシューに掲示・更新する。 壊しうる実装はしないため、夜通し何度回しても安全。

/mape-execute · 壊しうる

Execute（1周1件）

計画イシューのうちチェック済み・未着手の項目を1周に1件だけ実装する。 pytest が緑ならドラフト PR、赤なら破棄して記録。冪等にチェックを付けてコメントを残す。

承認ゲートは GitHub 計画イシューに掲示されるリスク3分類のチェックリスト（自動 / 承認 / 相談）です。 投資助言化・実データや実発注に関わるもの・秘密や課金は「相談」、合成データで実データを偽装する提案は却下、 という不変条件が分類に織り込まれています。人がチェックを入れた項目だけが Execute の対象になります。

自動 承認 相談

設計・分類・ガードレール・スケジュールの詳細は docs/mape-k.md ↗。 測定対象である夜間フォーキャストの仕組みは Forecast ページにあります。

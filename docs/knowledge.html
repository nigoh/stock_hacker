100文書のナレッジベース

なぜ知識をコードの外に置くのか。指標の計算はコードにできますが、 その数字をどう読むかの枠組みはコードになりません。 PBR 1倍割れが何を意味するのか、モメンタムが日本で効きにくいのはなぜか、 バックテストのどこが嘘をつくのか——判断の前提を Markdown で明示しておくことで、 レポートの解釈が属人的な勘ではなく、参照可能な出典を持つようになります。 断定的な将来予測ではなく、制度・数理・実証の整理として保つのが規約です。

Conventions

書き方の規約

100文書が索引として機能し続けるのは、書式が揃っているからです。規約は CLAUDE.md の 「ナレッジベースの規約」節にあり、/learn（knowledge-doc スキル）から文書を追加するときも同じ規約が適用されます。

1ファイル = 1トピック
ひとつの Markdown にひとつの主題。大きくなりすぎたら分割し、相互リンクで繋ぐ。関連文書は本文冒頭で参照する。
ファイル名は英語ケバブケース
例: nikkei-225-mechanics.md、valuation-metrics.md。grep しやすく、ディレクトリ一覧が索引として読める。
本文は日本語
制度・実務の一次情報が日本語であるため、訳し戻しによる劣化を避ける。用語は英語併記でよい（例: 経済的堀 / moat）。
冒頭に # タイトル と3行以内の要約
最初の数行だけで「この文書が何を扱い、何を扱わないか」が分かること。索引 00-index.md の1行紹介はこの要約から作る。
数式は LaTeX 記法
インラインは $...$、ブロックは $$...$$。例: 株式デュレーション $1/(r-g)$、シャープレシオの t 統計量。言葉での説明と数式を必ずセットにする。
追加・更新したら必ず 00-index.md に反映
索引が正であり、本文と乖離させない。リポジトリでは PostToolUse フック（scripts/check_knowledge_index.py）が索引未反映の文書を検出してブロックする。人手の規律ではなく機械のガードレールにしてある。
具体的な数値には「〜年時点」を付記
税率・制度の閾値・API の料金プランは変わる。例:「譲渡益課税20.315%（2025年時点）」「無料プランは12週間遅延（2026年時点）」。時点を書かない数値は、いずれ静かに嘘になる。
最も重要な規約 投資助言ではなく知識の整理であることを意識し、断定的な将来予測は書かない。 ナレッジベースが扱うのは、制度がどう決まっているか・数式が何を仮定しているか・実証研究が何を報告したかであって、 「この銘柄は上がる」ではありません。アノマリーの記述には多重検定と減衰の注意を、 実証結果には期待リターンと実現リターンの区別を必ず添えます。 この姿勢は生成されるレポートの免責（stocklib.report.DISCLAIMER）まで一貫しています。

22の分析コマンド

すべての CLI はリポジトリルートから python3 analysis/<command>.py で起動し、 結果を reports/ の Markdown レポートとして残します。 共通ライブラリ analysis/stocklib/ の上に載っているので、 期間指定・データソース切替・合成データ・基準通貨併記といった約束は コマンドをまたいで同じ形で効きます。

Conventions

共通の約束

個々のコマンドを読む前に、22本すべてに共通する入出力の作法を押さえておくと迷いません。 オプションの完全な一覧は各 CLI の --help が正です。

ユニバースの偏り（生存者バイアス） 同梱の liquid30.csv（2025年時点）・large70.csv（2026年時点、69銘柄）は、 その時点で上場・存続していた大型高流動性銘柄を後から選んだリストです。 上場廃止・経営破綻した銘柄を含まないため、過去に遡る集計（バックテスト・ブレッシュ・季節性・ペア・相対強度）は 生存者バイアスで実力より良く出ます。また小型株・新興株の挙動は代表していません。 詳細は backtesting-and-statistics.md。
Input · 銘柄コード

4桁で渡す

銘柄コードは4桁数字（例 7203）で渡し、内部の normalize_code が 7203.T に正規化します。^N225・1306.T・USDJPY=X のような指数・ETF・為替ティッカーはそのまま渡せます。

Output · reports/

Markdown で残る

結果は reports/<種別>-<日付>.md に保存され、そのパスが stdout に出ます （stocklib.report.save_report）。免責文は保存時に自動付与されます。 reports/ は gitignore 対象です。

Cache · data/cache/

価格は CSV キャッシュ

取得した価格系列は data/cache/ に CSV で保存され、再実行では再利用されます。 data/ は gitignore 対象なので、保有情報やキャッシュがコミットされることはありません。

Charts · reports/img/

図は PNG で埋め込み

チャートを持つ CLI は PNG を reports/img/ に出してレポートへ埋め込みます。 matplotlib が無い環境では警告してチャートなしに自動で縮退します。

コマンドをまたぐ共通オプション

--period PERIOD
価格の取得期間（yfinance 形式の 6mo / 1y / 2y / 5y / max 等）。 既定値はコマンドごとに違います（例: compare 1y / run_backtest 2y / market_breadth 2y / seasonality_report max）。各コマンドの項に明記しています。
--synthetic
ネットワーク不要の合成価格データ（シード固定）で全機能を動かします。20の CLI が対応 （非対応は価格データを使わない asset_plan.py と build_universe.py）。 合成データで作ったレポートは「手法のデモであり実データではない」ことが本文に明記されます。実データが取れないときに合成データで当日の市況を装うのは、この環境では禁止事項です。
--source {yfinance,jquants}
日足 OHLCV の取得元を切り替えます（19の CLI が対応。非対応は asset_plan.py / build_universe.py / fundamentals_report.py）。優先順位は --source > 環境変数 STOCK_HACKER_SOURCE > 既定 yfinance。 jquants は JQUANTS_API_KEY が必要・日足のみ・無料プランは12週間遅延。指数と為替は J-Quants 非対応のため自動で yfinance にフォールバックし、PER/PBR 等の fetch_info は常に yfinance を使います。
--in-currency {USD,EUR,GBP}
海外投資家視点で基準通貨建ての評価を併記します。対応は6コマンド （analyze_stock / compare / screen / run_backtest / portfolio_review / daily_brief）。 対応通貨は stocklib.currency.SUPPORTED_CURRENCIES のホワイトリスト（2026年時点で USD/EUR/GBP）。--in-usd は --in-currency USD の後方互換エイリアスです。
--no-charts
チャート PNG の生成・埋め込みを無効化します。対応は analyze_stock / compare / run_backtest / asset_plan の4コマンド。 図の生成がボトルネックになる一括実行や、テキストだけで足りる自動実行で使います。

自動実行契約（RESULT 行と exit code）

Routine / cron からの定期実行を想定する9つの CLI は、機械可読な契約を持ちます。 stdout の最終行に RESULT ... を出力し、 実データが1件も取れなかった場合は exit 2（data=unavailable・レポート非生成）、 CSV 不正などの引数エラーは exit 1（RESULT 行なし）、正常終了は exit 0 です。 通知の振り分け方は docs/automation.md に整理されています。

CLIRESULT 行
daily_brief.pyRESULT signals=<検出総数> watch=<成功>/<総数> data=<real|synthetic|unavailable>
market_breadth.pyRESULT breadth=<成功>/<総数> ad_ratio=<値|na> data=<…>
relative_strength.pyRESULT rs=<算出数>/<総数> valuation=<PER取得数> data=<…>
sector_rotation.pyRESULT sectors=<セクター数> covered=<成功>/<総数> data=<…>
risk_report.pyRESULT var95=<値> maxdd=<値> data=<…>
seasonality_report.pyRESULT months=<集計月数> years=<年数> data=<…>
pairs_screen.pyRESULT pairs=<評価ペア数> mean_reverting=<候補数> data=<…>

overnight_forecast.pyforecast: RESULT forecasts=<件数> universe=<成功>/<総数> data=<…> ／ grade: RESULT graded=<採点数> pending=<残保留> data=<…> ／ run: 両者を合成 ／ calibration: RESULT graded=<件数> data=real

残り13の CLI は RESULT 行を持たず、成功時にレポートパスを stdout に出力します。

Category 01 · single

個別銘柄 — 1銘柄を深く見る

analyze_stock.py
単一銘柄の総合分析レポートを生成します。テクニカル指標・ファンダメンタルズ・リスク指標・ シグナル検出・ベンチマーク相対をひとつの Markdown にまとめ、ローソク足チャートを埋め込みます。 
$ python3 analysis/analyze_stock.py 7203 --period 2y --benchmark ^N225
$ python3 analysis/analyze_stock.py 7203 --horizon mid --in-currency USD
位置引数 code（必須）。--period（既定 2y。--horizon 指定時は short=6mo / mid=2y / long=5y）、--benchmark（既定 ^N225）、--horizon {short,mid,long}、--synthetic、--source、--no-charts、--in-currency {USD,EUR,GBP}（--in-usd はエイリアス）。 出力: reports/analyze-<code>[-<horizon>]-<日付>.md。スキル /analyze から起動できます（Skills）。
fundamentals_report.py
業績（決算）の時系列分析。売上・利益・マージンの推移と成長率を集計します。 業績数値は yfinance の income_stmt / balance_sheet / cashflow が第一ソースです。 
$ python3 analysis/fundamentals_report.py 7203 --years 5
位置引数 code（必須）。--years（取得する最大年数、既定 5）、--synthetic。このコマンドに --source はありません（財務データは yfinance のみ）。 環境変数 EDINET_API_KEY があれば、EDINET API v2 で直近の有価証券報告書・四半期/半期報告書の一覧（docID 付き）を原文確認の導線としてレポートに添えます。出力: reports/fundamentals-<code>-<日付>.md。
risk_report.py
年率リターン・ボラだけでは見えない「下方への偏り」と「テールの厚み」を集計します。 下方偏差（MAR=0, 年率）・ソルティノレシオ・ヒストリカル VaR / 期待ショートフォール（ES/CVaR）95%・99%・ 最大ドローダウンとその最長継続日数・直近ボラの全期間分布パーセンタイルを出します。 
$ python3 analysis/risk_report.py 7203 --period 5y --vol-window 21
位置引数 code（必須）。--period（既定 2y）、--vol-window（ローリング年率ボラの窓、営業日、既定 21 ≒ 1ヶ月）、--synthetic、--source。 自動実行契約あり: RESULT var95=<値> maxdd=<値> data=<…>。VaR/ES は過去分布に基づく推定でテールを過小評価しうる旨がレポートに注記されます。
seasonality_report.py
単一銘柄／指数の長期価格から暦効果を集計します。月別平均リターンと勝率、曜日別平均リターン、 月内（月初/月末）効果、半期比較（Sell in May: 5〜10月 vs 11〜4月）を、 各集計に標本数 n を併記した形で出します。 
$ python3 analysis/seasonality_report.py ^N225
$ python3 analysis/seasonality_report.py 7203 --period 10y --first-days 3 --last-days 3
位置引数 code（必須。4桁は .T 正規化、^N225 等の指数も可）。--period（既定 max）、--first-days（月初の立会日数、既定 3）、--last-days（月末の立会日数、既定 3）、--synthetic、--source。 自動実行契約あり: RESULT months=… years=… data=…。月×曜日×期間の探索は本質的に多重検定であり、データスヌーピングで偶然のアノマリーが生じうる旨がレポートに明記されます。
Category 02 · cross

横断・市場全体 — 銘柄をまたいで見る

screen.py
ユニバース CSV（列 code,name,sector）の全銘柄を条件で絞り込みます。 テクニカル（RSI・SMA・期間リターン）、出来高、バリュエーション（PER・PBR・配当利回り）の条件を 自由に組み合わせられます。結果テーブルは stdout にも出ます。 
$ python3 analysis/screen.py --universe analysis/universe/liquid30.csv \
      --rsi-below 30 --price-above-sma 200
絞り込み条件: --rsi-below / --rsi-above（RSI(14)）、--price-above-sma N / --price-below-sma N、--volume-surge X（直近出来高が過去20日平均の X 倍以上）、--return-below PCT / --return-above PCT、--per-below X、--pbr-below X、--dividend-yield-above PCT。 その他: --universe（既定 analysis/universe/liquid30.csv）、--period（既定 1y）、--synthetic、--source、--in-currency。PER/PBR/配当利回りの条件は値が取得できない銘柄を除外します。出力: reports/screen-<日付>.md。
compare.py
指定した2銘柄以上の相対パフォーマンスと相関を比較します。期首=100 の相対推移図、 年率リターン・年率ボラ・シャープ・最大ドローダウン、日次リターンの相関行列を出します。 
$ python3 analysis/compare.py 7203 6758 9984 --period 1y
位置引数 codes（2つ以上）。--period（既定 1y）、--synthetic、--source、--no-charts、--in-currency。出力: reports/compare-<codes>-<日付>.md（stdout にもレポート本文を出します）。
daily_brief.py
市況（^N225・1306.T・USDJPY=X・^GSPC の前日比・5日・1ヶ月リターン）と、 ウォッチリスト各銘柄の現在値・前日比・検出シグナルを1本にまとめます。定期自動実行の主役です。 
$ python3 analysis/daily_brief.py --watchlist data/watchlist.csv
RESULT signals=4 watch=12/12 data=real
--watchlist（既定 data/watchlist.csv。列 code,note。無い場合は雛形を案内して市況のみで続行）、--period（既定 1y。52週高安・75日線の判定には 1y 以上を推奨）、--max-alerts N（シグナル詳細の表示を種別優先度の上位 N 件に絞る）、--synthetic、--source、--in-currency。 部分失敗（一部銘柄だけ取得できない）でも data=real のまま継続し、失敗銘柄はレポートの「取得失敗」節に列挙されます。signals=0 が「変化なし」なのか「取得できず監視に穴」なのかは watch= の分子分母で区別します。出力: reports/brief-<日付>.md。
market_breadth.py
指数の水準だけでは見えない「上昇の裾野の広さ」を、ユニバースの銘柄群から機械的に集計します。 終値が SMA25/75/200 を上回る銘柄割合、前日比の騰落数、騰落レシオ（25日）、52週新高値/新安値を出します。 
$ python3 analysis/market_breadth.py
$ python3 analysis/market_breadth.py --universe analysis/universe/large70.csv
--universe（既定 analysis/universe/liquid30.csv）、--period（既定 2y。SMA200・騰落レシオ25日の算出に 1y 以上を推奨）、--synthetic、--source。 自動実行契約あり: RESULT breadth=<成功>/<総数> ad_ratio=<値|na> data=<…>。ブレッシュは機械的な内部状態の記述であり、将来の騰落の予測ではない旨がレポートに注記されます。出力: reports/breadth-<日付>.md。
relative_strength.py
ユニバースの中で相対的に強い銘柄と、同セクター中央値に対して倍率の低い銘柄をクロスセクションで順位づけします。 3/6/9/12ヶ月モメンタムの加重合成を 1〜99 のパーセンタイル（RS ランク）にし、 あわせて各銘柄の PER/PBR の同セクター中央値に対する乖離を出します。 
$ python3 analysis/relative_strength.py --top 10
$ python3 analysis/relative_strength.py --no-valuation   # PER/PBR 取得を省いて高速化
--universe（既定 liquid30）、--period（既定 2y。12ヶ月モメンタムに 1y 以上を推奨）、--top（RS 上位/下位の表示件数、既定 10）、--no-valuation、--synthetic、--source。 自動実行契約あり: RESULT rs=<算出数>/<総数> valuation=<PER取得数> data=<…>。RS が高い＝過去に強かった、であって将来を保証しません。出力: reports/relative-<日付>.md。
sector_rotation.py
各銘柄の複数期間モメンタム（1/3/6/12ヶ月）をセクター単位に中央値で集約し、 代表窓（3ヶ月）の相対強度順にリーダー／ラガードを並べます。 セクター内ブレッシュ（終値 > SMA50 の割合）も併記します。 
$ python3 analysis/sector_rotation.py
$ python3 analysis/sector_rotation.py --universe data/universe/jquants-all.csv
--universe（既定は analysis/universe/large70.csv。他の横断系 CLI と既定が違う点に注意）、--period（既定 2y）、--synthetic、--source。 自動実行契約あり: RESULT sectors=… covered=<成功>/<総数> data=…。セクター分類はユニバース CSV の sector 列に依存し、少数銘柄のセクターは不安定になります。出力: reports/sector-<日付>.md。
catalyst_radar.py
各銘柄の次の決算発表日・配当落ち日を Yahoo Finance のカレンダーから取得し、 指定日数以内に到来するイベントを接近順に並べます。決算後ドリフト（PEAD）や 権利落ちなど、イベントドリブンの起点を機械的に把握するためのツールです。 
$ python3 analysis/catalyst_radar.py --within 14
--universe（既定は data/watchlist.csv、無ければ liquid30 にフォールバック）、--within（何日以内のイベントを対象にするか、既定 30）、--synthetic、--source。 自動実行契約あり: RESULT events=… covered=<成功>/<総数> data=…。イベント日は取得日時点の予定であり変更されうる（確定ではない）旨がレポートに注記されます。出力: reports/catalyst-<日付>.md。
adr_parity.py
東証の現地株・米国 ADR・ドル円の3つを突き合わせ、乖離を機械的に測ります。 理論 ADR 価格 = 東証終値 × ADR比率 ÷ ドル円、乖離% = ADR終値 / 理論値 − 1、 円換算 ADR 価格 = ADR終値 × ドル円 ÷ ADR比率（東京閉場後に米国市場で付いた価格の情報（翌朝の始値を予測する値ではない））を並べます。 
$ python3 analysis/adr_parity.py 7203
$ python3 analysis/adr_parity.py --all      # adr_map.csv の全銘柄
位置引数 codes（0個以上。analysis/universe/adr_map.csv に登録済みの銘柄のみ）。--all（対応表の全銘柄）、--period（既定 1mo。直近終値のみ使用）、--synthetic、--source。 東証と米国市場では終値の暦日がずれるため、乖離には時差由来の成分が含まれます。ADR 比率は対応表の登録値（2025年時点、要確認）です。出力: reports/adr-<日付>.md。
Category 03 · strategy

戦略検証 — ルールを過去データにぶつける

run_backtest.py
売買ルールのバックテスト。戦略とバイ&ホールドの統計（トータル/年率リターン、年率ボラ、 シャープ、最大ドローダウン、取引回数、勝率、t統計量、対象営業日数）を並べ、資産曲線を埋め込みます。 戦略は ma_cross / rsi_reversal / macd / bollinger_reversal / dca の5種類です。 
$ python3 analysis/run_backtest.py --strategy ma_cross --code 7203 \
      --fast 25 --slow 75 --cost-bps 10 --split 0.7 --sweep
$ python3 analysis/run_backtest.py --strategy dca --code 7203 --monthly 30000
共通: --strategy（既定 ma_cross）、--code（必須）、--period（既定 2y）、--cost-bps（片道取引コスト bps、既定 10）、--split R（時間順で前 R をインサンプル、残りをアウトオブサンプルとして並記）、--sweep（パラメータ近傍グリッドを走らせ試行回数 N と成績分布を表化。--split 併用時は IS 区間のみ）、--synthetic、--source、--no-charts、--in-currency。 戦略別パラメータ: ma_cross は --fast（既定 25）/ --slow（75）。rsi_reversal は --rsi-window（14）/ --rsi-lower（30）/ --rsi-upper（50）。macd は --macd-fast（12）/ --macd-slow（26）/ --macd-signal（9）。bollinger_reversal は --bb-window（20）/ --bb-std（2.0）。dca は --monthly（30000）/ --day-of-month（1）。 出力: reports/backtest-<strategy>-<code>-<日付>.md。--sweep の試行回数は多重検定の分母として必ず読むこと（後述の「特筆すべき挙動」参照）。
pairs_screen.py
ユニバースの全ペアについて、対数価格の連動性とスプレッドの平均回帰の強さを測ります。 ヘッジ比β・スプレッドの Dickey-Fuller 統計量・OU 半減期・現在の z スコアを算出し、 平均回帰の強い順に候補を並べます（実装は numpy のみ）。 
$ python3 analysis/pairs_screen.py --same-sector --top 20
--universe（既定 liquid30）、--period（既定 3y。共和分の推定には長めを推奨）、--top（表示ペア数、既定 15）、--same-sector（同セクターのペアのみ＝経済的な連動の裏付けがあるペアに絞る）、--min-overlap（評価に必要な最小の重なり営業日数、既定 250）、--synthetic、--source。 自動実行契約あり: RESULT pairs=… mean_reverting=… data=…。N銘柄で N(N−1)/2 ペアを検定する多重比較のため偽陽性が出やすく、インサンプルの統計であり将来の平均回帰を保証しません。空売りコストも考慮外です。出力: reports/pairs-<日付>.md。
Category 04 · portfolio

保有・資産 — 自分の口座を測る

このカテゴリの CLI は data/portfolio.csv / data/transactions.csv を読みます。 data/ は gitignore 対象なので、個人の保有情報がコミットされることはありません。 雛形は analysis/templates/ にあります。

portfolio_review.py
保有 CSV から評価額・損益・セクター配分・加重β・相関・年率ボラ・VaR・HHI 集中度・ 下落ストレス感応度（β近似）をまとめます。CSV の任意列によってレポートの節が増える設計です。 
$ python3 analysis/portfolio_review.py --file data/portfolio.csv --period 1y
$ python3 analysis/portfolio_review.py --drift-band 5.0 --in-currency USD
--file（既定 data/portfolio.csv）、--period（既定 1y）、--benchmark（β計算のベンチマーク、既定 ^N225）、--drift-band（目標配分ドリフトの閾値バンド %pt、既定 5.0）、--synthetic、--source、--in-currency。 CSV の任意列: account（NISA口座状況の節）、target_weight（目標配分とのドリフト節）、manual_price（投信・現金など手入力評価行）、proxy_ticker（手入力行をリスク指標に組み込むための上場プロキシ）、fx_at_cost（基準通貨建て損益の分解）、acquired_date・memo。 下落ストレス感応度の節は常に入り、ベンチマークが −10%/−20%/−30% 下落した場合の推定損益を ΔV ≈ Σ MV_i·β_i·Δm で試算します（予測ではなくβ一定仮定の感応度試算。ストレス時はβ・相関が上昇しがちという限界も併記）。出力: reports/portfolio-<日付>.md。
income_report.py
保有銘柄ごとに直近12ヶ月（TTM）の実績1株配当 × 株数で年間受取配当見込みを推計し、 取得原価ベースの YOC・時価ベースの配当利回り・税引後の手取り・月割り額をまとめます。 
$ python3 analysis/income_report.py --file data/portfolio.csv --period 1y
--file（既定 data/portfolio.csv）、--period（時価利回りの分母となる現在値の取得期間、既定 1y）、--synthetic（合成配当系列＝シード固定・年2回の半期配当）、--source。 account 列があれば NISA分を非課税・課税口座分を源泉徴収 20.315%（2025年時点）として手取りを併記し、NISA分の非課税メリット（年間フロー = NISA分税引前配当 × 20.315%）を試算します。NISA配当の非課税には株式数比例配分方式の選択が必要である旨が必ず注記されます。 manual_price を持つ行（投信・現金など）は配当・価格の取得対象外で、年間配当 0 として集計されます。TTM 実績は会社予想ではなく将来の配当を保証しません（減配リスク）。出力: reports/income-<日付>.md。
tax_report.py
課税口座（特定・一般）ポジションの銘柄別含み損益と、含み損銘柄を 「実現した場合の税価値（試算）」= 含み損 × 20.315%（2025年時点の申告分離課税率）を一覧します。 NISA 口座の含み損が損益通算・繰越控除の対象外であることも対比表示します。 
$ python3 analysis/tax_report.py --file data/portfolio.csv --period 1y
--file（既定 data/portfolio.csv）、--period（既定 1y）、--synthetic、--source。 実務上の注意——同一銘柄の同日買い戻しで取得単価が平均化され実現できる損失が縮む点、繰越控除には確定申告が必要な点、税価値のために投資判断を歪める本末転倒（tax tail wagging the dog）——が本文に自動挿入されます。 この CLI は「実現した場合の」条件付き試算に徹する情報整理であり、損出し・売却・保有継続の判断はしません。出力: reports/tax-<日付>.md。
performance_report.py
取引履歴 CSV から「自分の運用はこれまで実際に年率何%だったのか」を測ります。 金額加重リターン（MWR = XIRR）をニュートン法＋二分法フォールバックで解き、 期間損益の内訳（実現 + 未実現 + 受取配当）と、同じキャッシュフローをベンチマークに投じた場合の比較を出します。 
$ python3 analysis/performance_report.py --file data/transactions.csv
$ python3 analysis/performance_report.py --benchmark 1306.T   # 配当込みの比較
--file（既定 data/transactions.csv。列 date,code,side,shares,price,fee,account,memo。side は buy / sell / dividend / deposit / withdraw）、--benchmark（既定 ^N225）、--period（省略時は最初の取引日から自動導出）、--synthetic、--source。 入出金行があれば口座モード、約定のみならポジションモードに自動判定します。既定の ^N225 は配当を含まない価格指数なので、配当込みで比べるなら分配金調整済みの 1306.T 等を指定します。テンプレート: analysis/templates/transactions-example.csv。出力: reports/performance-<日付>.md。
asset_plan.py
資産形成プランニング。価格データもネットワークも使わない唯一系統の CLI で、 決定論的複利とモンテカルロのファンチャートつきレポートを出します。 サブコマンドは project（積立予測）/ goal（目標額から必要積立額を逆算）/ progress（現在資産と積立ペースでの到達確認＝要求リターン逆算・到達確率）/ decumulate（定額・定率取り崩し）の4つです。 
$ python3 analysis/asset_plan.py project --monthly 50000 --years 20 --return 5 --nisa
$ python3 analysis/asset_plan.py goal --target 30000000 --years 25 --return 4
$ python3 analysis/asset_plan.py progress --target 30000000 --years 15 \
      --current 8000000 --monthly 70000 --return 4
$ python3 analysis/asset_plan.py decumulate --initial 30000000 --years 30 \
      --return 3 --vol 12 --rate 4
全サブコマンド共通: --return（必須、想定年率リターン。%表記で 5 = 年率5%）、--vol（想定年率ボラ、%表記）、--inflation（%表記、既定 0）、--cost（信託報酬等の年率コスト、%表記、既定 0。実効リターン $(1+R)(1-c)-1$ で計算し前提表に控除後リターンを明記）、--paths（モンテカルロのパス数、既定 2000）、--seed（既定 42、固定で再現可能）、--no-charts。 サブコマンド別: project は --monthly / --years（必須）・--initial・--nisa（課税口座 20.315%〔2025年時点〕との比較を併記）。goal は --target / --years（必須）・--initial。progress は --target / --years / --current / --monthly（すべて必須）。decumulate は --initial / --years（必須）＋ --monthly（定額）か --rate（定率、%表記）のいずれか、--inflation-linked。 --synthetic も --source もありません（そもそも価格データを引きません）。想定リターンはユーザー入力の仮定であり、将来の保証ではない旨がレポートに必ず明記されます。出力: reports/plan-<サブコマンド>-<日付>.md。
Category 05 · forecast

予想と記録 — 出した予想を必ず採点する

この2本がこの環境の閉ループの実体です。予想も仮説も、記録した時点で採点の期日が決まります。 設計と運用の詳細は Forecast にあります。

overnight_forecast.py
「寝ている間に翌営業日へ向けて予想を出し、翌日その予想の答え合わせをして、 実績を台帳（forecasts/ledger.csv）に貯めていく」ループを回します。 予想は RSI・移動平均の並び・モメンタムの固定重み合成で、方向・上昇確率・予想リターン・ ATR ベースの予想レンジを出します。 
$ python3 analysis/overnight_forecast.py run          # grade → forecast（夜間実行の本体）
$ python3 analysis/overnight_forecast.py forecast     # 翌営業日の予想を生成して台帳に追加
$ python3 analysis/overnight_forecast.py grade        # pending 予想を実績で採点
$ python3 analysis/overnight_forecast.py calibration  # 的中率・Brier・較正を集計
共通: --ledger（実績台帳 CSV、既定 forecasts/ledger.csv。主にテスト用）。各サブコマンド: --period（既定 1y。75日線・モメンタムに 1y 以上を推奨）、--synthetic、--source。forecast と run はさらに --universe（既定は data/watchlist.csv、無ければ liquid30。code 列必須、name / note 列は任意）。 自動実行契約あり（サブコマンドごとに RESULT 行が異なる。上の 契約表 参照）。--synthetic で作った予想は台帳に data=synthetic と記録され、実データの実績とは採点されません。 出力: forecasts/ledger.csv（git 管理対象）＋ reports/forecast-<日付>.md / forecast-grade-… / forecast-run-… / forecast-calibration-…。予想は機械的なベースラインであり、売買助言でも将来の断定でもありません。
research_journal.py
「分析のやりっぱなし」をなくすためのツール。仮説を journal/<YYYY>/<日付>-<slug>.md に 記録時点の終値を自動スナップショットして残し、検証予定日が来たら現在値と 同期間のベンチマーク騰落を突き合わせて hit / miss / mixed を機械判定します。 
$ python3 analysis/research_journal.py new --codes 7203 \
      --title "決算後の上方修正期待" --direction up --review-days 60
$ python3 analysis/research_journal.py due     # 検証期日が来た open エントリ
$ python3 analysis/research_journal.py verify journal/2026/2026-07-16-….md
$ python3 analysis/research_journal.py list    # 全エントリのサマリー
共通: --journal-dir（既定 journal/。主にテスト用）。new: --codes（必須、複数可）、--title（必須）、--direction（up/down/neutral か 7203:up,6758:down の銘柄ごと指定）、--review-days（既定 60）、--benchmark（既定 ^N225）、--slug、--synthetic、--source。verify: 位置引数 path、--synthetic、--source。due / list は価格を取得しません（--synthetic は一貫性のため受け付けるだけ）。 new --synthetic は frontmatter に data: synthetic を書き込み、verify はエントリの data と --synthetic 指定が食い違うと拒否します（合成スナップショットと実データの比較は判定として無意味なため）。雛形の生成後、## 仮説 / ## 根拠 / ## 反証条件 を必ず記入します。
Category 06 · data

データ基盤 — 分析の入力を用意する

build_universe.py
J-Quants の全上場銘柄一覧（stocklib.jquants.fetch_listed_info()）から、 screen.py 互換の code,name,sector CSV を生成します。 liquid30 / large70 を超える全銘柄スクリーニングの入口です。 
$ set -a && source .env && set +a     # JQUANTS_API_KEY を読み込む
$ python3 analysis/build_universe.py --market プライム --sector33 銀行
$ python3 analysis/screen.py --universe data/universe/jquants-all.csv --rsi-below 30

Gotchas

特筆すべき挙動

--help の一行だけでは読み取りにくい、挙動が大きく変わるオプションと入力列をまとめます。

analyze_stock · --horizon

--horizon short|mid|long は投資時間軸のフレームです。指定すると 該当時間軸の「視点」節がレポートに追加され（short: 5/25日線・RSI・ATR倍数のストップ目安・出来高急増・直近20日高安値／ mid: 25/75/200日線の並び・3/6/12ヶ月モメンタム・52週高値からの距離／ long: 年率リターンとボラ・最大ドローダウン・配当利回り・PBR/PER の長期文脈・積立適性）、 --period 未指定時の取得期間が short=6mo / mid=2y / long=5y に変わり、 出力ファイル名も analyze-<code>-<horizon>-<日付>.md になります。 省略時は従来どおりの全部入り（期間 2y、ファイル名も従来どおり）です。

run_backtest · --strategy dca

dca だけは売買シグナル戦略ではなく、毎月定額買付（ドルコスト平均法）の積立 シミュレーションです。--monthly（毎月の買付金額、円、既定 30000）と --day-of-month（目標買付日 1〜31。非営業日や月に無い日は翌営業日に繰越、既定 1）を取り、 累計投資額と同額を期初に一括投資した場合との比較表・チャートを出します。 --split / --sweep / --in-currency とは併用できません（円建てのみ）。

portfolio_review · account 列

保有 CSV の任意列 account（nisa_tsumitate / nisa_growth / taxable。 空欄・列なしは taxable 扱い）が1銘柄でもあると、レポートに「NISA口座状況」節が追加されます。 口座区分別の簿価・評価額・損益、年間投資枠（つみたて投資枠120万円・成長投資枠240万円/年）と 生涯投資枠（1,800万円、うち成長投資枠1,200万円。簿価残高方式）の使用率、 非課税メリット推計（NISA含み益 × 20.315%）を出します。 いずれも2024年開始の新NISA制度の値、税率は2025年時点のものです。 保有中の銘柄の簿価のみからの集計で売却済み分・投資信託の買付を含まないため、 金融機関側の枠残高管理値とはずれうる点に注意してください。 account=nisa_tsumitate に上場銘柄コードがある場合は「つみたて投資枠では個別株は購入できない（2024年制度）」という警告が出ます（エラーにはしません）。

共通 · --in-currency の換算方法

基準通貨建ての換算はクロス円レート（USDJPY=X / EURJPY=X / GBPJPY=X）の 同日終値によるヘッジなし近似です。リターンは恒等式 $(1+r^{B})=(1+r^{JPY})/(1+r^{FX})$ に従います。 コマンドごとに効き方が違います——screen は各銘柄の O/H/L/C を換算してから RSI・SMA・リターン条件を評価します （PER/PBR/配当利回りは通貨に依存しない比率なので円建てのまま、出来高は無変換）。 run_backtest は売買シグナルを常に円建て価格で計算し、確定した日次リターンだけを換算します （換算後の価格でシグナルを出すと、執行と乖離したルックアヘッド類似の歪みが入るため）。 portfolio_review では評価額・年率ボラ・VaR は全銘柄で計算しますが、損益の基準通貨建て併記は 任意列 fx_at_cost（取得時のクロス円レート）がある銘柄に限られ、未入力の銘柄は円建てのみで注記されます。

--synthetic の禁止事項

--synthetic はネットワーク不要で手法を動かすための合成データです。 自動実行で実データが取れないときに --synthetic で代替して「今日の市況」のように見せることは禁止です。 RESULT 行を持つ CLI はこの場合 data=unavailable ＋ exit 2 で静かに終了するよう作られています。 合成データで作ったレポートには必ず「合成データによる手法デモであり実データではない」と明記してください。

読むときの構え

既定のデータソースは yfinance（非公式 API）です。日本株では分割・配当調整の不備が起きうるため、 レポートで異常な騰落やギャップを見たらまずデータ品質を疑ってください。 重要なレポートを外部共有や意思決定に使う前には、敵対的レビュー（/review-report）を通す運用になっています。 レビュー観点は Skills、指標の理論的背景は Knowledge、 予想の評価指標（的中率・Brier・較正）は Forecast を参照してください。

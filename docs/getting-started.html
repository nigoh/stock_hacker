Getting started · 所要 3〜5分

clone して、依存を入れて、最初のレポートを出す。

このページを上から順にたどると、環境構築 → 最初の分析レポート生成 → 自分の保有データの登録 → データソースの任意設定 → つまずいたときの対処まで、ひと通り動く状態になります。 ネットワークが使えない環境でも --synthetic で全機能を確認できます。

Step 01 · Requirements

必要なもの

必要なのは Python 3.11 以上と、requirements.txt の依存パッケージだけです。 分析 CLI は素の Python スクリプトで、ノートブックもデータベースも要りません。 Claude Code から対話で使う場合はスキル / スラッシュコマンドの層も加わりますが、 CLI は Claude Code 無しでも単体で動きます。

Runtime

Python 3.11+

analysis/ 配下は型ヒント前提の Python 3.11+ で書かれています。python3 --version で確認してください。

Data

ネットワーク（任意）

既定のデータソースは yfinance のため実データには外部接続が要ります。使えない場合は --synthetic で全 CLI が動きます。

Optional

API キー（任意）

J-Quants（JQUANTS_API_KEY）と EDINET（EDINET_API_KEY）は任意設定。未設定でも基本機能は動きます。

依存パッケージ（requirements.txt）

パッケージバージョン用途
pandas>=2.2価格・財務データの表操作（全 CLI の土台）
numpy>=1.26指標・統計計算（ペア共和分検定なども numpy のみで実装）
yfinance>=0.2.40既定のデータソース。日足 OHLCV と PER/PBR 等の基本情報
requests>=2.31EDINET / J-Quants など HTTP 経由のデータ取得
matplotlib>=3.8チャート PNG の生成。未導入でも自動でチャートなしに縮退する任意依存
pytest>=8.0テスト（ネットワーク不要で実行できる）
Step 02 · Install

インストール

クローンして依存を入れ、テストで動作確認します。テストはネットワーク不要です。

# 1. 取得する
$ git clone https://github.com/nigoh/stock_hacker.git
$ cd stock_hacker

# 2. 依存パッケージを入れる
$ pip install -r requirements.txt

# 3. 動作確認（ネットワーク不要）
$ python3 -m pytest analysis/tests

CLI はリポジトリのルートから実行します。生成物の置き場所 （reports/ と data/cache/）は初回実行時までに用意されていれば十分で、 Claude Code で開いた場合は SessionStart フック（scripts/session_start.sh）が ディレクトリ作成・依存パッケージの確認・stocklib のインポート確認を自動で行い、 使えるコマンドの要点をセッションの文脈に注入します。

Claude Code は必須ではない スキル・スラッシュコマンド（/analyze 等）は Claude Code 上の入り口ですが、 手順の実体は analysis/*.py の CLI です。CLI を直接叩けば同じレポートが得られます。 全オプションは各 CLI の --help で確認できます。
Step 03 · First report

最初の分析

個別銘柄の総合分析を1本走らせます。7203 はトヨタ自動車です。

# 個別銘柄の総合分析（既定の取得期間は 2y、既定のベンチマークは ^N225）
$ python3 analysis/analyze_stock.py 7203 --period 2y --benchmark ^N225
reports/analyze-7203-2026-07-24.md

# 時間軸フレームを指定すると「視点」節が加わり、ファイル名にも入る
$ python3 analysis/analyze_stock.py 7203 --horizon mid
reports/analyze-7203-mid-2026-07-24.md

実行するとレポートのパスが標準出力に出ます。中身は次の節で構成されます （--horizon short|mid|long を付けた場合は該当時間軸の「視点」節が追加され、 --period 未指定時の取得期間が short=6mo / mid=2y / long=5y になります）。

レポートの節入るもの
基本情報企業名・セクター・PER / PBR・配当利回りなど（yfinance の基本情報）
価格サマリー直近終値と期間内の騰落・高安
チャートreports/img/ に PNG を生成して埋め込む。上段=ローソク足+SMA+ボリンジャーバンド、中段=出来高、下段=RSI(14)
テクニカル指標SMA(25/75/200) と終値の位置関係・RSI(14)・MACD(12,26,9) など
リスク・リターン指標年率リターン・年率ボラティリティ・シャープレシオ・最大ドローダウン・ベンチマーク対比のβ
免責投資助言ではなく分析支援である旨（stocklib.report が自動付与）

銘柄コードの渡し方

銘柄は4桁の数字で渡します（内部で yfinance の 7203.T 形式に正規化されます）。 指数・為替のティッカーは正規化せずそのまま渡せます。

7203 → 7203.T ^N225 そのまま USDJPY=X そのまま 1306.T そのまま

取得した価格データは data/cache/ に CSV でキャッシュされます（gitignore 済み）。 チャートが不要なら --no-charts で無効化できます。

Step 05 · Your data

自分のデータを置く

保有・ウォッチ・取引の CSV は analysis/templates/ のテンプレートを data/ にコピーして編集します。 

$ cp analysis/templates/portfolio-example.csv    data/portfolio.csv
$ cp analysis/templates/watchlist-example.csv    data/watchlist.csv
$ cp analysis/templates/transactions-example.csv data/transactions.csv
# 中身を自分の保有・ウォッチ銘柄・取引履歴に書き換える
個人データはコミットされない設計 data/.gitignore が data/ 配下のファイルをすべて git 管理外にしています。 保有情報・ウォッチリスト・取引履歴・価格キャッシュが誤ってコミット・公開されることは原則ありません（git add -f で明示的に強制した場合を除く）。 逆に、git 管理対象である journal/（リサーチジャーナル）には保有情報を書かず、 検証可能な分析仮説だけを書きます。

data/portfolio.csv（portfolio_review / income_report / tax_report で使用）

列必須内容
code必須銘柄コード4桁（例 7203）。投信・現金は任意の識別子でよい（例 emaxis-slim-allcountry、cash）
shares必須保有数量
avg_cost必須平均取得単価（円）
acquired_date任意取得日 YYYY-MM-DD。NISA 年間投資枠の暦年集計に使う
memo任意メモ
fx_at_cost任意取得時のクロス円レート。--in-currency 指定時に損益を株価要因と為替要因へ分解する
account任意口座区分 nisa_tsumitate / nisa_growth / taxable（空欄は課税口座扱い）。記入すると NISA 枠の節が有効になる
target_weight任意目標ウエイト（%）。目標配分からの乖離チェックに使う
manual_price任意yfinance で価格が取れない資産（投信等）の1口あたり現在価額を手入力。現金は avg_cost=1 / manual_price=1。この行は配当集計の対象外
proxy_ticker任意連動 ETF 等の代理ティッカー。指定するとリスク指標の計算に組み込む

code と note の2列。^N225 のような指数ティッカーも書けます。

Step 06 · Data sources（optional）

データソース（任意）

既定のデータソースは yfinance で、特に設定しなければ全 CLI がこれで動きます。 以下はすべて任意設定です。

yfinance の制約は先に知っておく yfinance は非公式 API です。日本株では分割・配当調整の不備や欠損が起きることが知られており、 auto_adjust=True は配当込み調整のため他ソースの系列と一致しません。 レポートで異常な騰落やギャップを見たら、まずデータ品質を疑うこと。 重要なレポートにはデータソースと取得日を明記します。

J-Quants（JPX 公式・全上場銘柄）

jpx-jquants.com の無料プラン登録後にダッシュボードで発行した API キーを JQUANTS_API_KEY に設定すると、日足 OHLCV を J-Quants から取得できます （V2・API キー方式・無期限。2025年12月の V2 移行でリフレッシュトークン方式は廃止、2026年時点）。 

# ① コマンドごとに指定
$ python3 analysis/analyze_stock.py 7203 --source jquants

# ② セッション全体で既定を切り替える（全 CLI に効く）
$ export STOCK_HACKER_SOURCE=jquants

# ③ 全上場銘柄から screen.py 互換のユニバース CSV を作る
$ python3 analysis/build_universe.py

優先順位は --source 引数 > STOCK_HACKER_SOURCE > 既定の yfinance。押さえておく点は次のとおりです。

  • 無料プランは12週間遅延データ（2026年時点）。当日のブリーフや直近の相場観測には向かず、用途は学習・バックテスト・全銘柄ユニバース構築。
  • 日足のみ対応。^N225 等の指数と USDJPY=X 等の為替は J-Quants が扱わないため自動で yfinance にフォールバックします。
  • PER / PBR などの基本情報（fetch_info）は常に yfinance を使います。切り替わるのは OHLCV だけです。
  • 銘柄コードは J-Quants 側が5桁、配当調整の扱いも yfinance と非互換です。系列をまたいで比較するときは注意します。

EDINET（法定開示書類）

有価証券報告書などの検索・取得には EDINET_API_KEY を設定します （API v2 はキー必須、2024年時点）。未設定でも業績分析は yfinance の財務データで動作します。

.env で読み込む

キーは .env（gitignore 済み。雛形は .env.example）に置き、シェルで読み込む運用を推奨します。

$ cp .env.example .env       # JQUANTS_API_KEY=... を記入
$ set -a && source .env && set +a
キーを漏らさない API キーをコード・レポート・コミットに含めないこと。 .env は gitignore 済みですが、レポート本文やコマンド履歴の貼り付けから漏れることがあります。 キーが漏れた疑いがあればダッシュボードで再発行してください。
Step 07 · Offline

ネットワークが無いとき

価格データを使う全 CLI 共通で --synthetic が使えます。 シード固定の合成データ（幾何ブラウン運動 + ボラティリティクラスタ）で全機能が動くため、 接続できない環境でも仕組みの確認・手法のデモができます。 asset_plan.py はそもそも価格データもネットワークも使わないため対象外です。 

# yfinance への接続に失敗したら --synthetic を付けて再実行する
$ python3 analysis/analyze_stock.py 7203 --synthetic
$ python3 analysis/screen.py --rsi-below 30 --synthetic
合成データの扱い（厳守）

合成データで作ったレポートには、「合成データによる手法デモであり実データではない」ことを必ず明記します （CLI 経由ならレポートに自動で明記されます）。

そして自動実行で実データが取れないときに --synthetic で代替し、 「今日の市況」のように見せることは禁止です。デイリーブリーフや夜間フォーキャストは、 実データが全滅した場合はレポートを生成せず exit 2 で静かに終了する契約になっています。 合成データを実データの代替として使ってはいけません。

Step 08 · Troubleshooting

困ったら

症状原因と対処
Connection reset / Failed to perform で価格が取れない まず python3 scripts/smoke_realdata.py で切り分ける。価格・基本情報・指数・為替の4経路を個別に判定し、http_429（UA・レート制限）か dns / conn_reset（ネットワーク不達）かを種別で表示する。不達なら実行環境のネットワーク許可設定を確認するか J-Quants を設定する。手法を試すだけなら --synthetic を付ける
データ層（stocklib/data.py 等）を直したが壊していないか不安 pytest は全て合成データ・モックで、実データ経路の健全性を保証しない。 python3 scripts/smoke_realdata.py で実疎通を確認する（過去に User-Agent の変更で実データ取得が壊れたのに、テスト682件は全て緑だった）。ネットワーク必須のため CI には含めていない
JQuantsAuthError が出る API キーが未設定か無効。jpx-jquants.com のダッシュボードで発行し .env の JQUANTS_API_KEY を更新する。V2 移行でリフレッシュトークン方式は廃止されており、旧 JQUANTS_REFRESH_TOKEN は使えない
--source jquants なのに価格が古い 仕様どおり。無料プランは12週間遅延データのため、当日ブリーフ用途には使えない。直近が要るなら既定の yfinance に戻す
レポートにチャートが埋め込まれない matplotlib が未導入。標準エラーに警告を出したうえでチャートなしで続行する設計。必要なら pip install matplotlib、不要なら --no-charts で明示的に無効化する
レポートの書き込みが「免責文が無い」で止まる PostToolUse フック（scripts/check_report_disclaimer.py）が正しく働いている。stocklib.report の保存関数を使えば免責が自動付与される（CLI 経由なら自動）
knowledge/ に文書を足したら書き込みがブロックされた PostToolUse フック（scripts/check_knowledge_index.py）が索引未反映を検出している。knowledge/00-index.md にエントリを追加すれば通る（/learn は索引反映まで自動で行う）
レポートの騰落・ギャップが明らかにおかしい まずデータ品質を疑う。yfinance は非公式 API で、日本株では分割・配当調整の不備が起きうる。重要な判断の前は他ソースと突き合わせる
環境が壊れていないか確かめたい python3 -m pytest analysis/tests -q（ネットワーク不要）。CLI 側は --help で全オプションを確認できる
どのコマンドを使うか迷う 目的別の索引は CLI リファレンス、対話の入り口は Skills。Claude Code 上なら「7203 を長期目線で見たい」のような自然文でも適切なスキルが選ばれる

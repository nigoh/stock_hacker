# 日本株データソースとAPI

日本株の分析に使える主要データソース（J-Quants API、EDINET、TDnet、日銀・e-Stat、yfinance、株探・IRバンク等）を、無料・有料の使い分けと取得実務の注意点まで含めて整理する。特に米国株と異なる日本固有の事情——適時開示の仕組み、銘柄コードの形式、株式分割・単元制度に伴う調整——を重点的に扱う。Pythonでの取得例と、調整後株価・コーポレートアクション処理の落とし穴も解説する。

## 全体像：日本株データの入手経路

日本株データは大きく「取引所・公的機関系（一次情報）」と「民間サービス系（加工情報）」に分かれる。歴史的に日本の個人投資家向けデータ環境は米国に比べて貧弱で、無料APIはほぼ存在しなかったが、2022年に日本取引所グループ（JPX）系の **J-Quants API** が正式提供を開始し（2023年に有料プラン本格化）、状況が大きく改善した。

| データソース | 提供元 | 内容 | 料金（2025年時点の目安） |
|---|---|---|---|
| J-Quants API | JPX総研 | 株価四本値、財務、コーポレートアクション、信用残等 | 無料（12週遅延）〜プレミアム月額数万円 |
| EDINET API | 金融庁 | 有価証券報告書・四半期報告書・大量保有報告書（XBRL） | 無料 |
| TDnet | 東証 | 適時開示（決算短信、業績修正等） | 閲覧無料（公式APIなし） |
| 日銀時系列データ / e-Stat | 日本銀行 / 総務省 | 金利、マネーストック、短観、CPI、GDP等 | 無料（e-StatはAPIあり） |
| yfinance | Yahoo Finance非公式 | 株価（`.T`サフィックス）、簡易財務 | 無料（非公式・規約注意） |
| 株探・IRバンク・バフェットコード | 民間 | スクリーニング、長期業績、決算速報 | 無料〜月額数千円 |

## J-Quants API：日本株分析の事実上の標準

JPX総研が提供する公式API。個人が正規ルートで東証全銘柄の調整済み株価と財務データを取得できる初の公的サービス。2026年時点でプランは概ね以下（月額、詳細は変更されうる）。

- **Free（¥0）**：12週間遅延データ・格納約2年窓。バックテストの学習用途には十分。
- **Light（¥1,650）/ Standard（¥3,300）/ Premium（¥16,500）**：遅延なし、過去データ収録期間の拡大（Light 5年 / Standard 10年 / Premium 20年）、投資部門別・TOPIX/指数・信用残・空売り・先物/オプション・財務諸表・配当・売買内訳などが上位プランで段階的に解放。分足/Tick・TDnet はアドオン（Light 以上）。

> **⚠ V1→V2 移行（2025年12月〜、2026年時点）**: J-Quants は 2025/12/22 に **V2** へ刷新され、認証が「リフレッシュトークン→IDトークンの2段階方式（V1）」から「**APIキー方式（V2）**」に変わった。API キーは**無期限**（V1 の約1週間の期限は撤廃）。旧 V1 は並走期間を経て**廃止**された。エンドポイントのパスも全面改称（例 `/v1/prices/daily_quotes` → `/v2/equities/bars/daily`、`/listed/info` → `/equities/master`）、レスポンスは `data` 配列＋`pagination_key`、四本値カラムは短縮形（`O`/`H`/`L`/`C`/`Vo`、調整済み `AdjO`/`AdjC` 等）。

取得例（2026年時点・V2 APIキー方式。`x-api-key` ヘッダのみで、V1 のトークン交換は不要）:

```python
import requests

headers = {"x-api-key": "<APIキー>"}  # ダッシュボードで発行（無期限）
# 日次株価（銘柄コードは5桁形式: トヨタ7203 → "72030"）
r = requests.get(
    "https://api.jquants.com/v2/equities/bars/daily",
    headers=headers, params={"code": "72030", "from": "2024-01-01"})
rows = r.json()["data"]  # 調整済みは AdjO/AdjH/AdjL/AdjC/AdjVo、未調整は O/H/L/C/Vo
```

注意点として、J-Quantsの銘柄コードは**5桁**（従来の4桁コード＋予備桁）である。また調整済み系列（`AdjC` 等）と未調整系列（`C` 等）の両方が返るため、どちらを使っているか常に意識する必要がある。レート制限はプラン別（Free 5 / Light 60 / Standard 120 / Premium 500 リクエスト/分、2026年時点）。全 API 横断の比較は `market-data-apis-catalog.md` を参照。

本リポジトリには J-Quants V2 への接続モジュール `analysis/stocklib/jquants.py` が実装済みである。環境変数 `JQUANTS_API_KEY` に API キー（無期限、https://jpx-jquants.com/ の無料プラン登録後にダッシュボードで発行）を設定すれば、`stocklib.jquants.fetch_daily_quotes()` が `fetch_prices()` と同じ OHLCV DataFrame 形式で日足四本値を返し、`fetch_listed_info()` で上場銘柄一覧（全銘柄スクリーニングのユニバース構築用。V2 の短縮カラム名は V1 相当の安定名に正規化して返す）を取得できる。4桁コード → 5桁コードの正規化と、分割・併合調整済み系列（`AdjC` 等）の優先利用はモジュール側で自動処理される。外部依存は標準ライブラリ + pandas のみで、`requests` は不要。

## EDINET APIとTDnet：開示情報の一次ソース

**EDINET**（金融庁）は法定開示書類の電子開示システムで、無料APIを持つ。有価証券報告書・四半期報告書・大量保有報告書（5%ルール報告）がXBRL形式で取得でき、`5%超の大量保有変動`をイベントドリブン戦略のシグナルに使う実務も多い。2024年以降はAPI利用にAPIキー登録が必要になった（2025年時点）。書類一覧は `documents.json` エンドポイントに日付を渡して取得し、`docID` を指定してZIP（XBRL）をダウンロードする流れになる。XBRLの解析には `Arelle` や `edinet-xbrl` 系のライブラリが使われるが、タクソノミの版差異に注意が必要である。なお四半期報告書は2024年4月の金商法改正で廃止され、半期報告書に一本化された（2024年時点）。

本リポジトリには EDINET API v2（`https://api.edinet-fsa.go.jp/api/v2/`）への接続モジュール `analysis/stocklib/edinet.py` が実装済みである。環境変数 `EDINET_API_KEY` にAPIキー（利用登録ページで無料発行）を設定すれば、`stocklib.edinet.search_documents("7203")` が日付レンジを遡って有報（docTypeCode=120）・四半期/半期報告書（140/160）の一覧を DataFrame で返し（EDINETの `secCode` は5桁のため4桁コード+`0`で自動照合）、`fetch_document_csv(docID)` が書類取得API（type=5）のzipから財務諸表CSV（XBRL項目の縦持ち、UTF-16タブ区切り）を DataFrame にして返す。書類一覧APIは1リクエスト=1日分の設計のため、長期間の検索は日数分のHTTP GETになる点に注意。業績数値の時系列分析には `stocklib/fundamentals.py`（yfinance の財務諸表を正とし、EDINETは原文確認用と位置づける設計）と CLI `analysis/fundamentals_report.py` を使う。

**TDnet**（東証・適時開示情報伝達システム）は決算短信・業績予想修正・自己株買いなどの適時開示の配信元で、日本株の株価を最も動かす情報源といってよい。日本企業は米国と異なり**決算短信**（速報、監査対象外）→**有価証券報告書**（法定、監査済）の二段構えで開示する点が固有の文脈である。TDnet自体に公式APIはなく、ウェブ閲覧（当日を含め直近1か月分程度）が基本。プログラムからの利用はスクレイピングか、適時開示をアーカイブする民間サービス経由になる。決算発表は15:00（2024年11月以降の取引時間延長後は15:30、2025年時点）の大引け後に集中する慣行があり、PEAD（決算後ドリフト）研究ではタイムスタンプの扱いが重要になる。

## マクロ統計：日銀時系列データとe-Stat

- **日銀時系列統計データ検索サイト**：無担保コール翌日物金利、マネーストック、資金循環、短観のDI等。公式REST APIはないがCSV一括ダウンロードが整備されている。短観の業況判断DIは $DI = (\text{良いと答えた企業の割合}) - (\text{悪いと答えた企業の割合})$ で定義され、日本株のマクロタイミング分析で頻用される。
- **e-Stat API**（総務省統計局）：CPI、労働力調査、家計調査などをJSON/XMLで取得できる無料API（要アプリケーションID登録）。統計表IDを指定して取得する設計で、`statsDataId` の特定が最初の関門になる。

## yfinance：手軽さと引き換えのリスク

Yahoo Financeの非公式ラッパー。東証銘柄はティッカーに `.T` を付ける（例：トヨタは `7203.T`）。

```python
import yfinance as yf
df = yf.download("7203.T", start="2020-01-01", auto_adjust=True)
```

利点は手軽さと世界市場との横断比較のしやすさだが、(1) 非公式であり仕様変更・取得失敗が頻発する、(2) 商用利用は規約上問題がある、(3) 日本株の配当・分割データの精度が米国株より低い、という制約を理解して「プロトタイピング用」と割り切るのが実務的である。名証・福証・札証銘柄は `.NG` 等のサフィックスだが収録は不完全である。

## 情報サイト：株探・IRバンク等

- **株探（かぶたん）**：決算速報の速さと「決算売買」文化の中心。プレミアム（有料）で過去25期以上の業績データ閲覧が可能（2025年時点）。
- **IRバンク**：EDINETデータを整理した無料サイト。長期の業績・配当・自社株買い履歴の確認に便利。
- **バフェットコード**：財務データの横断スクリーニング。無料枠＋有料プラン。
- **JPX公式サイト**：投資部門別売買状況（海外投資家の売買動向）、空売り集計、裁定取引残高など、日本市場固有の需給データが無料で取れる点は見逃せない。

## 調整後株価とコーポレートアクションの注意点

バックテストの品質を最も左右するのが株価調整の扱いである。株式分割・併合があった場合、分割比率 $r$（1株→$r$株）に対して過去の株価と出来高は

$$
P_t^{adj} = \frac{P_t^{raw}}{r}, \qquad V_t^{adj} = V_t^{raw} \times r
$$

と調整する（分割日より前の系列に適用）。直感的には「分割は価値を変えずに株数だけ増やす」ので、系列の連続性を保つには過去の価格を分割後の1株基準に引き直す必要がある、ということである。複数回のアクションがあれば調整係数は累積積になる。

日本固有の注意点：

1. **単元株制度と株式分割の頻発**：東証は最低投資金額を50万円未満に抑えるよう要請しており（2025年時点）、値がさ株の分割が制度的に誘発される（例：2024年前後のNTT 25分割、ファーストリテイリング3分割）。分割調整を怠ると「株価が突然1/25になった」偽シグナルが生まれる。
2. **配当調整の有無**：J-Quantsの `AdjustmentClose` は分割・併合調整のみで**配当落ち調整は含まれない**（2025年時点の仕様）。トータルリターンを計算するなら配当を別途加算する必要がある。yfinanceの `auto_adjust=True` は配当込み調整で、両者の系列は一致しない。
3. **銘柄コードの変転**：合併・持株会社化でコードが変わる（例：旧コードの再利用もある）。コードだけで時系列を繋ぐと別会社を接合する事故が起きるため、上場廃止・新規上場の履歴（J-Quantsの上場銘柄一覧APIで取得可能）と突き合わせる。
4. **生存者バイアス**：無料ソースは上場廃止銘柄を含まないことが多い。廃止銘柄込みのユニバースを作れるのはJ-Quants上位プランや有料データベンダーに限られる。

## 無料でリアルタイムに近い株価を得ることの限界

「無料で今この瞬間の正確な株価を、機械処理できる形で得る」手段は、日本株では事実上存在しない。これは制約というより市場データ産業の構造であり、無料ソースを選ぶ前に理解しておくべき前提である。

### 鮮度の階層（2025年時点）

| 鮮度 | 代表的な入手手段 | 機械処理 | 精度 | 主な用途 |
|---|---|---|---|---|
| リアルタイム（遅延なし） | 有料ベンダー（QUICK・Refinitiv 等）、J-Quants 有料プラン | ○（API） | 高 | 遅延なし運用・板配信 |
| 即時（自分の口座画面） | 証券会社アプリ/Web の株価・板 | ×（閲覧のみ・再配信不可） | 高 | 発注タイミングの判断 |
| 数十分遅延 | Yahoo!ファイナンス（サイト）、株探、yfinance（非公式 API） | Web=×／yfinance=△ | 中（yfinance は調整に難） | 目視確認・プロトタイピング |
| 即時（開示のみ） | TDnet（適時開示） | ×（公式APIなし） | 高 | 決算・材料の把握 |
| 12週間遅延 | J-Quants Free | ○（API） | 高（分割・併合調整済み） | 学習・バックテスト |

### なぜ無料のリアルタイム API が存在しないのか

取引所のリアルタイム相場は、東証の情報ベンダー制度のもとでライセンス料を伴って配信され、ベンダーはその再配信に課金する。個人が無料で正規に得られるのは、原理的に次の2つに限られる。

1. **遅延配信データ**（Yahoo!ファイナンス等の数十分遅延、J-Quants Free の12週間遅延）——再配信のハードルが下がる代わりに鮮度を犠牲にしたもの。
2. **自分の証券口座の画面**——リアルタイムだが、規約上**再配信・スクレイピング・自動収集は禁止**されているのが通常で、機械処理には使えない。

つまり「鮮度」「機械処理可否」「無料」の3つは同時に満たせない（トリレンマ）。無料で取れるものは、リアルタイムなら閲覧のみ、機械処理できるなら遅延あり、のどちらかになる。

### 実務的な含意

- **バックテスト・戦略研究・過去分析**：鮮度は不要なので J-Quants Free（12週遅延・調整済み・高精度）が最適。yfinance は near-real-time だが調整の不備があるため、研究の本番系列には J-Quants を優先する。
- **発注タイミングの判断**：リアルタイムが要るので、証券会社の画面・板（口座に付帯、無料だが閲覧のみ）や有料 API を使う。ここに無料の機械可読ソースを期待しない。
- **この2つを混同しない**。「無料の遅延データで発注判断する」「遅延データで作った集計を"今日の市況"として最新であるかのように見せる」のが典型的な事故である（本リポジトリの自動実行契約が、実データを取れないときに合成データで市況を偽装することを禁じているのも同じ理由）。

要するに、無料枠は**「過去を正確に機械処理する」用途に最適化されており、「現在を正確に機械処理する」用途は有料か口座付帯の閲覧に委ねられている**。この線引きを最初に引いておくと、データソース選びで迷わない。

## 無料と有料の使い分け指針

- 学習・戦略の当たり付け：J-Quants Free（遅延データ）＋yfinance＋IRバンク。
- 遅延なしの日次運用・イベントドリブン：J-Quants有料プラン＋EDINET API＋TDnet監視。
- 板情報・ティックデータが必要な高頻度分析：J-Quantsでも不足し、証券会社API（auカブコム kabuステーション、立花証券e支店等）や有料ベンダー（QUICK、Refinitiv）の領域になる。

「一次情報（EDINET/TDnet）で裏を取り、APIで系列を機械処理する」二層構えが、データ品質と開発効率を両立させる基本形である。

対象: $ARGUMENTS

分析成果物を **risk-officer サブエージェント**による敵対的レビューにかけること。自分でレビューを実施してはならない。手順は以下。

1. **対象の確定**
   - 引数にパスが指定されていればそれをレビュー対象とする。存在しないパスならユーザーに確認する。
   - 引数が空の場合は `reports/` の最新ファイルを対象とする（例: `ls -t reports/*.md | head -1`）。`reports/` にレポートが1つもなければ、その旨を伝えて対象パスをユーザーに確認する。
   - どのファイルをレビューするかをユーザーに明示してから次へ進む。
2. **risk-officer への委譲** — Task ツールで `risk-officer` サブエージェントを起動し、以下を依頼する。
   - レビュー対象のファイルパス（絶対パスまたはリポジトリルート相対）を明示する。
   - risk-officer 定義（`.claude/agents/risk-officer.md`）の手順に従い、`knowledge/math/backtesting-and-statistics.md` 等の関連 knowledge/ 文書を判定根拠として読み込んだうえで、敵対的レビューを実行させる。
   - 検出観点: **統計的誤り**（t統計量の欠落・多重検定未申告・年率化の誤り等）、**ルックアヘッド・バイアス**（シグナルと約定の同一足、生存者バイアス未言及、コスト仮定等）、**投資助言化**（断定的将来予測・売買推奨に読める記述・免責文欠落）、**合成データの偽装**（--synthetic 使用の明記なし。実データと誤認させる記述は最重大）。
   - バックテスト系レポートなら生成元スクリプト（`analysis/` 配下・stocklib）との数字の整合も検証させる。
3. **結果の報告** — risk-officer の指摘を**重大度の高い順**（重大 → 中 → 軽微）に、各指摘の「重大度・根拠・修正案」の形式のままユーザーに報告する。最後に総合判定（「差し戻し」「条件付き可」「可」）を明示する。
4. **後続の扱い** — 指摘の修正はこのコマンドの範囲外。ユーザーが修正を求めた場合のみ、指摘の修正案に沿って対応する（risk-officer 自身は Write/Edit 権限を持たない）。

このレビューは品質検証であり投資助言ではない。レビューを通ったことは投資判断の正しさを保証しない。

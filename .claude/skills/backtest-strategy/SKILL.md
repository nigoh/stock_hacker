# 戦略バックテストと統計的検証

対象: $ARGUMENTS

売買戦略を過去データで検証し、**「儲かって見える結果」を統計的に疑う**ところまでを一つの作業として行う。バックテストの数字を出すだけでは完了ではない。検証されていないバックテストは投資判断の材料にならない。

## 手順

### 1. 必読ナレッジ（実装前に必ず読む）

- `knowledge/math/backtesting-and-statistics.md` — **必読**。t検定・多重検定・各種バイアス・ウォークフォワードの枠組み。本スキルのチェックリストの根拠
- `knowledge/00-index.md` — 戦略の種類に応じた関連文書を洗い出す

さらに戦略タイプに応じて追加で読む:

- 移動平均・オシレーター系 → `knowledge/technical/indicators-and-ichimoku.md`
- ファクター系（バリュー・モメンタム等） → `knowledge/strategies/factor-investing-japan.md`
- 季節性・アノマリー系 → `knowledge/strategies/market-anomalies-and-seasonality.md`
- ペア・裁定系 → `knowledge/strategies/pairs-trading-and-arbitrage.md`
- 取引コストの置き方 → `knowledge/strategies/execution-algorithms-and-transaction-costs.md`
- ポジションサイズ・リスク管理 → `knowledge/strategies/risk-management-and-position-sizing.md`

### 2. 戦略仮説の明文化（実装前に書き切る）

コードを書く前に、以下を明文化してユーザーと共有する。**仮説を先に書き、試行回数を記録する**（後述の多重検定補正に必要）:

1. **経済的仮説** — なぜ効くはずなのか（例: トレンド追随は行動バイアスによるアンダーリアクションを収益源とする）。「なんとなく効きそう」は仮説ではない
2. **エントリールール** — シグナルの定義を数式・条件式で（例: SMA25 が SMA75 を上抜けた翌営業日の寄付で買い）
3. **イグジットルール** — 手仕舞い条件（反対シグナル・損切り・保有期間上限）
4. **執行の仮定** — シグナル判定の足と約定の足を分ける（**当日終値でシグナル判定して当日終値で約定、はルックアヘッド**。翌日寄付または翌日終値で約定させる）
5. **取引コスト** — 片道何bpsか。手数料+スプレッドで最低10bps、小型株ならより保守的に。`--cost-bps` に反映する
6. **検証期間と分割** — 全期間、インサンプル（IS）/アウトオブサンプル（OOS）の切り方

### 3. バックテストの実行

組み込み戦略（`ma_cross`: 移動平均クロス、`rsi_reversal`: RSI閾値による逆張り）はリポジトリルートから実行する:

```bash
python3 analysis/run_backtest.py --strategy ma_cross --code 7203 --fast 25 --slow 75 --cost-bps 10
python3 analysis/run_backtest.py --strategy rsi_reversal --code 7203 --rsi-window 14 --rsi-lower 30 --rsi-upper 50 --cost-bps 10
```

さらに検証用フラグを併用する（手順4・5のチェックを CLI だけで実行できる）:

- `--split 0.7` — 時間順で前70%を IS、残りを OOS とし、両区間の統計テーブルを並記する
- `--sweep` — 指定パラメータの近傍グリッドを走らせ、試行回数 N と成績分布を表化する（`--split` 併用時は IS 区間のみでスイープ）

- 成功すると統計レポート（総リターン・年率リターン・年率ボラ・シャープレシオ・最大ドローダウン・取引回数・勝率等）が生成される
- **ネットワークが使えない場合**は `--synthetic` を付けて再実行し、最終レポートに「合成データによる手法デモであり実データではない」ことを必ず明記する
- 銘柄コードは4桁数字（例: `7203`）。内部で `7203.T` に正規化される

組み込みにない戦略は `analysis/` にスクリプトを新規作成し、`stocklib.backtest` を使ってカスタム実装する:

- `analysis/stocklib/data.py` でデータ取得（`--synthetic` 相当の合成データ関数も利用可）
- `analysis/stocklib/indicators.py` の指標関数を再利用し、車輪の再発明をしない
- Python 3.11+・型ヒント必須。シグナル列は必ず `shift(1)` 等で1営業日以上遅らせてから約定させる（ルックアヘッド防止の実装原則）
- コスト控除は取引発生時にポジション変化量 × cost_bps で差し引く

### 4. インサンプル / アウトオブサンプル分割

パラメータを1つでも調整（最適化）するなら必ず分割する。組み込み戦略なら `--split 0.7` で自動化できる:

1. 期間の前 70〜80% を IS、残りを OOS とする（時間順序を保つ。ランダム分割は不可）
2. パラメータ調整・戦略の修正は **IS のみ**で行う
3. OOS は最終確定した1本の戦略に対して**一度だけ**走らせる。OOS の成績を見てパラメータを直したら、その時点で OOS は IS に汚染されたとみなし、レポートにその旨を明記する
4. 余力があればウォークフォワード（IS最適化→直後OOS評価をローリングし、OOS成績のみ連結）を行う
5. IS と OOS の成績（シャープレシオ・最大DD）を並記する。**OOS が IS より大きく劣化していれば過剰適合の強い証拠**

### 5. 統計的検証チェックリスト（全項目必須）

`knowledge/math/backtesting-and-statistics.md` に基づき、以下を全て確認してレポートに結果を記載する:

- [ ] **t統計量** — $t \approx SR_{\text{annual}} \times \sqrt{Y}$（$Y$=年数）で概算する。目安として **t < 2 は「偶然と区別できない」、実務では t > 3 を要求**。年率SR 0.5 で t>2 に達するには約16年のデータが必要——数年分の検証で SR 0.5 を「有意」と書かない
- [ ] **多重検定** — 試したパラメータ組み合わせ・戦略バリエーションの総数 $N$ を申告する。$N$ 個の無価値戦略でも少なくとも1つが5%有意になる確率は $1-(1-0.05)^N$（N=20で約64%）。最良の組み合わせの成績は額面どおり解釈せず、ボンフェローニ的に有意水準を $\alpha/N$ で見るか t>3 を要求する
- [ ] **ルックアヘッドバイアス** — シグナル判定に使うデータが約定時点で入手可能だったかをコードで確認する（シグナルの shift、財務データなら発表日ベースか）
- [ ] **生存者バイアス** — 検証ユニバースが「現在生き残っている銘柄」だけで構成されていないか。`analysis/universe/liquid30.csv` は2025年時点の現存主要銘柄であり、複数銘柄検証ではこのバイアスを免れない——その限界を必ず明記する
- [ ] **取引コスト** — コストゼロの成績を報告しない。コストあり/なしを並記し、コスト感応度（例: 10bps→30bps で戦略が生き残るか）を示す。回転率の高い戦略ほどここで死ぬ
- [ ] **成績の集中** — 損益が特定の数日・特定レジーム（例: 2024年8月急落）に集中していないか。可能なら年別・レジーム別に分解する
- [ ] **パラメータ頑健性** — 最良パラメータの近傍（例: fast 25→20/30）でも成績が維持されるか。わずかな変更で激変するなら過剰適合を疑う。組み込み戦略なら `--sweep` で近傍グリッドの成績分布と試行回数 N が表化される

### 6. レポートの作成と保存

`reports/backtest-<strategy>-<code>-<日付>.md` に以下の章立てで保存する:

1. **戦略仮説** — 手順2で明文化した内容（経済的仮説・ルール・コスト仮定・試行回数 $N$）
2. **実行条件** — データ期間、IS/OOS 分割、使用コマンド、合成データか実データか
3. **バックテスト結果** — IS/OOS 別の統計テーブル（年率リターン、SR、最大DD、取引回数、勝率、コスト後）
4. **統計的検証** — 手順5のチェックリスト全項目の結果
5. **結論** — 下記の報告様式に従う
6. **免責** — 末尾に必ず入れる（下記）

### 7. 報告様式：有望に見えても過剰適合を疑う

結論は必ず次の温度感で書く:

- 結論は「有意な優位性は確認できなかった」「優位性を否定できないが t=X.X で統計的証拠は弱い」「複数の頑健性チェックを通過したが、なお過剰適合の可能性は残る」のいずれかの形を基本とする。**「この戦略は儲かる」とは書かない**
- 良い結果が出たときほど疑う。「なぜこの結果は偶然・バイアスの産物でありうるか」という節を必ず設け、最低2つの懐疑シナリオ（例: 試行回数の未計上、特定レジーム依存、コスト過小評価）を挙げる
- 悪い結果も報告価値がある。「効かなかった」という知見として何が棄却されたかを明確に書く
- 断定的な将来予測は書かない。過去の統計的性質の記述に徹する

### 8. 免責文（必須）

レポート末尾に必ず以下を入れる:

> 本レポートは分析手法の提示と過去データの統計的検証を目的としたものであり、投資助言ではありません。バックテストの成績は将来の運用成果を保証しません。投資判断はご自身の責任で行ってください。

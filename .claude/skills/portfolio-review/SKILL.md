# ポートフォリオ評価・リスクレビュー

対象ファイル: $ARGUMENTS

保有銘柄 CSV を読み込み、評価額・損益・セクター配分・市場感応度（β）・相関構造・集中度を定量評価し、ナレッジベースの枠組みで解釈したレビューレポートを作成する。

## 手順

### 1. ポートフォリオ CSV の確認

- 引数でパスが指定されていればそれを、省略時は `data/portfolio.csv` を使う。
- CSV の列は `code,shares,avg_cost,acquired_date,memo,fx_at_cost,account,target_weight,manual_price,proxy_ticker`（memo・fx_at_cost・account・target_weight・manual_price・proxy_ticker は省略可）。code は4桁の銘柄コード、acquired_date は `YYYY-MM-DD`。fx_at_cost は取得時のクロス円レート（円/基準通貨、正の数）で、基準通貨建て損益の算出に使う（下記 `--in-currency`）。
- target_weight は目標ウエイト（%。**全行入力・合計ほぼ100%** が必要。現金を配分に含めるなら code=cash の行を manual_price=1 で追加する）。この列がある CSV ではレポートに「目標配分とのドリフト」節（銘柄別/セクター別の乖離%pt、閾値バンド判定〔`--drift-band`、既定±5%pt〕、目標回帰の機械的な調整額試算）が自動で追加される。
- manual_price は手入力の現在値（投信の基準価額、現金は 1）。入力した行は yfinance を引かず手入力値で評価され（yfinance は国内投信の基準価額を取得できないため、現金・投信を含む全体資産ビューが作れる）、この行に限り code は4桁以外の識別子（`emaxis-slim-allcountry`、`cash` 等）でよい。proxy_ticker 未指定の手入力行は β・年率ボラ・VaR・相関の計算対象外で、**手入力値の取得日・鮮度の管理はユーザーの責任**（レポートに自動で注記される）。
- proxy_ticker は手入力行（manual_price 入力行）専用の任意列で、連動対象とみなす上場プロキシのティッカーを書く（例: 全世界株投信 → `2559.T`、TOPIX投信 → `1306.T`。**どの銘柄を連動対象とみなすかはユーザーの判断**であり、勝手に決めて記入しない——投信の連動指数を確認してもらってから案内する）。指定した行はプロキシの価格系列で β・年率ボラ・VaR・相関・下落ストレス感応度に組み込まれる（評価額は従来どおり manual_price）。**プロキシによる近似（信託報酬差・為替ヘッジ差・基準価額の1営業日ズレは反映されない）**である旨はレポートに自動で注記される。新NISAつみたて枠のコアが投信の場合、この列が無いと「最大の保有資産がリスク指標に写らない」状態になるため、投信のウエイトが大きい CSV に proxy_ticker が無ければ列の追加を案内する（既存 CSV はそのままでも動く）。
- account は口座区分（`nisa_tsumitate` / `nisa_growth` / `taxable`。空欄・列なしは taxable 扱い）。この列がある CSV ではレポートに「NISA口座状況」節が自動で追加される（下記手順 4-NISA）。ユーザーが NISA の話をしているのに CSV に account 列が無い場合は、列の追加を案内する（既存 CSV はそのままでも動く）。個別株（4桁コードの行）を `nisa_tsumitate` にしていると、レポートに「つみたて投資枠では個別株は購入できない（2024年制度）——口座区分の入力ミスの可能性」という警告が自動で出る（エラーにはならない）。警告を見たらユーザーに実際の口座区分を確認する。
- `data/portfolio.csv` が無い場合は、テンプレート `analysis/templates/portfolio-example.csv` を案内し、ユーザーに保有銘柄を確認してから作成する。勝手に架空の保有内容をでっち上げない。
- **設計上の注意（ユーザーにも一言添える）**: 保有情報は `data/` 配下に置く。`data/` は `.gitignore` 対象なので、個人の保有情報が誤って git にコミットされることはない。テンプレート（`analysis/templates/portfolio-example.csv`）だけがコミット対象。保有 CSV を `analysis/` や `knowledge/` など git 管理下のディレクトリにコピーしない。

### 2. 定量評価 CLI の実行

リポジトリルートから実行する:

```bash
python3 analysis/portfolio_review.py [--file <パス>] [--period 1y]
```

- `reports/portfolio-<日付>.md` が生成され、パスが stdout に出力される。内容は (1) 銘柄ごとの現在値・評価額・損益・損益率・ウエイト・β、(2) 合計損益、(3) セクター配分、(4) 加重β・年率ボラ・ヒストリカルVaR(95%)・HHI 集中度、(5) 日次リターン相関行列、(6) 下落ストレス感応度（β近似。ベンチマーク −10%/−20%/−30% 下落時の推定損失額・推定評価額）。
- 海外投資家視点の依頼（「ドル建てで評価して」「米国から見たリスクは？」）のときは `--in-currency USD|EUR|GBP`（`--in-usd` は `--in-currency USD` のエイリアス）を付ける。評価額・年率ボラ・VaR が基準通貨建てで併記される（クロス円レートの同日終値・ヘッジなし近似）。損益は CSV の任意列 `fx_at_cost`（取得時のクロス円レート）を入力した銘柄に限り基準通貨建てで併記され、「うち株価要因」「うち為替要因」に分解される。`fx_at_cost` の無い銘柄の損益は円建てのみ（現在為替での近似換算はしない）——この理由はレポートに自動で明記される。
- CSV のバリデーションエラー（列不足・数値不正・日付不正・コード重複）は行番号付きで stderr に出る。ユーザーに修正箇所をそのまま伝える。
- **ネットワークが使えない場合**は `--synthetic` を付けて再実行し、最終レポートに「合成データによる手法デモであり、実データではない」ことを必ず明記する。合成データでの損益・評価額は実際の保有状況とは無関係である点を強調する。

### 3. ナレッジベースを解釈の枠組みに使う

結果を解釈する前に、必ず以下を読む:

- `knowledge/math/portfolio-theory.md` — 分散効果・相関・βの理論的な意味
- `knowledge/strategies/risk-management-and-position-sizing.md` — 集中リスク・ポジションサイジング・VaR の限界

必要に応じて追加で読む:

- セクター偏りの文脈 → `knowledge/fundamental/sector-structure-japan.md`
- ボラ・VaR の前提（正規性・ファットテール） → `knowledge/math/returns-and-distributions.md`
- 下落ストレス感応度の読み方（生活防衛資金・リスク受容力との突き合わせ） → `knowledge/strategies/household-risk-capacity-and-allocation.md`
- NISA口座状況の解釈 → `knowledge/regulation-tax/taxation-and-nisa.md`（制度の正確な仕様: 税率20.315%・年間枠・生涯枠・簿価残高方式・損益通算不可）と `knowledge/regulation-tax/nisa-practical-strategies.md`（枠の使い方の実務的な考え方。無い場合は前者のみでよい）

### 4. 結果の解釈（レポートへの加筆）

生成されたレポートを土台に、以下の観点で解釈を加える:

1. **集中リスク** — HHI と実効銘柄数を読む。特定銘柄のウエイトが大きい場合、その銘柄の個別リスク（決算・不祥事等）がポートフォリオ全体を左右することを指摘する
2. **セクター偏り** — セクター配分の上位を確認。同一セクター集中は「銘柄数は多いのに分散できていない」状態になり得る。相関行列の高相関ペアと突き合わせる
3. **βの意味** — 加重β > 1 は市場（^N225）より値動きが大きい攻撃的な構成、< 1 は防御的な構成。市場急落時の想定感応度として文脈化する
4. **ボラ・VaR** — 「95%の日は1日の損失がX%以内」という読み方と、テールリスク（VaR を超える損失）は捉えられないという限界を必ず併記する
5. **相関** — 相関は期間依存・レジーム依存で、市場ストレス時に上昇しがち（分散効果が必要なときに効かない）ことを明記する
6. **NISA口座状況**（CSV に account 列がある場合のみレポートに出る）— 解釈の前に `knowledge/regulation-tax/taxation-and-nisa.md` と `knowledge/regulation-tax/nisa-practical-strategies.md` を読む。読み方:
   - **口座区分別の内訳** — NISA/課税口座それぞれの評価額・損益。NISA側に大きな含み損がある場合は「NISAは損益通算・繰越控除ができないため、含み損の非課税メリットはゼロで、むしろ課税口座より不利になりうる」ことを必ず指摘する
   - **枠の使用状況** — 年間投資枠（つみたて120万円・成長240万円、2024年制度）と生涯投資枠（1,800万円、うち成長投資枠1,200万円）に対する簿価ベースの使用率。CSV は保有中の銘柄のみの集計で、売却済み分・投資信託の積立を含まないため、実際の枠残高とはずれうる（レポートにも注記が自動で入る）。使用率が100%を超えて見える場合はまず CSV の入力（口座区分の誤り・売却済み行の残存）を疑う
   - **非課税メリットの推計** — NISA含み益 × 20.315%（2025年時点税率）は「課税口座なら将来課税されうる額」の目安であり、確定した節税額ではない。この額の大きさと生涯枠の残りを、ユーザー自身が「どの口座区分で何を保有するか」を考える材料として提示する
   - **売買指示はしない** — 「成長枠に移すべき」「NISAで買い直すべき」とは書かない。枠のトレードオフ（非課税メリット vs 損益通算不可・枠復活が翌年）を数値とともに示すにとどめる
7. **目標配分とのドリフト**（CSV に target_weight 列がある場合のみレポートに出る）— 乖離（%pt）・バンド判定・調整額はいずれも**機械的な測定・試算**であり、「どれを売って何を買うべき」とは書かない。解釈では (a) バンド方式の考え方（バンド内は放置がコスト効率的、`knowledge/math/portfolio-construction-in-practice.md` のリバランス設計）、(b) 摩擦（課税口座の売却は含み益に20.315%課税〔2025年時点〕、NISA年間枠は売却でも当年復活しない・生涯枠は翌年復活〔2024年制度〕、単元株・手数料）、(c) 売却を伴わない方法（新規拠出の配分調整）の存在、を必ず添える。手入力行（manual_price）が混ざる場合は評価時点のずれにも触れる
8. **下落ストレス感応度（β近似）**（レポートに常に出る）— 解釈の前に `knowledge/strategies/household-risk-capacity-and-allocation.md` を読む。読み方:
   - **試算の意味** — ベンチマークが −10%/−20%/−30% 下落した場合の推定損失額を $\Delta V \approx \sum_i MV_i \cdot \beta_i \cdot \Delta m$ で機械的に出した表であり、**予測ではなくβ一定仮定の感応度試算**。実際のストレス時はβ・相関が上昇しがちで損失は過小推定されうる（レポートに自動で注記される）——この限界を必ず引用する
   - **対象範囲を確認する** — β不明の手入力行（proxy_ticker 未指定の投信・現金）は「変動ゼロ扱い」で対象外。対象カバー率（評価額ベース）が低い場合は、試算がポートフォリオ全体を代表していないことを明示し、投信行への proxy_ticker 追加（連動対象の確認はユーザー）を案内する
   - **家計との突き合わせ** — 推定損失額（円）を「この損失が起きても生活設計・積立の継続が壊れないか」（生活防衛資金の月数、収入の安定性 = リスク受容力）という観点でユーザー自身が読むための材料として提示する。過去実績（2008年リーマン危機の TOPIX 年間約4割下落、2020年コロナショックの約3割急落。いずれも過去実績で将来を保証しない）はシナリオの現実味の文脈として添える
   - **安全宣言はしない** — 「この程度の下落なら耐えられる」「問題ない水準」のような判定・宣言は絶対に書かない。判断材料の提示にとどめる

### 5. 改善観点の提示（売買指示はしない）

- 「どの観点を再検討する余地があるか」（集中度・セクター偏り・β水準と本人のリスク許容度の整合）を**観点として**提示する。
- **特定銘柄の売買指示（「〜を売るべき」「〜を買い増すべき」）は絶対に書かない。** 本環境の出力は投資助言ではない。
- 事実（データ）・解釈（分析）・不確実性（わからないこと）を区別して書く。

### 6. 免責と品質ゲート

- レポート末尾に免責文を必ず入れる（CLI が `stocklib.report.DISCLAIMER` を自動付与するが、加筆後も残っていることを確認する）。
- **このレビューを資産配分の見直し等、重要な判断に使う前は必ず `/review-report` を通す**よう促す（risk-officer による敵対的レビュー）。

## 品質の基準

- 損益率・ウエイトなどの数値はすべて CLI の出力に基づく。手で再計算した値を混ぜない。
- 具体的な数値・制度（NISA 枠など）に言及する場合は「〜年時点」を付記する。
- 評価額・損益は直近終値ベースであり、リアルタイムの時価ではないことを明記する。

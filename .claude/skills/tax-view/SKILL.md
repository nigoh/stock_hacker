# 含み損益の税価値ビュー

対象ファイル: $ARGUMENTS

保有銘柄 CSV から課税口座（特定・一般）の銘柄別含み損益と「実現した場合の税価値（試算）」= 含み損 × 20.315%（2025年時点）を機械的に一覧し、NISA口座（損益通算・繰越控除の対象外）と対比した判断材料レポートを作成する。損出し・売却・保有継続のいずれの判断もしない。

## 手順

### 1. ポートフォリオ CSV の確認

- 引数でパスが指定されていればそれを、省略時は `data/portfolio.csv` を使う。列形式は portfolio-review スキルと同一（`code,shares,avg_cost,acquired_date,memo,fx_at_cost,account,target_weight,manual_price`）。
- 任意列 `account`（`nisa_tsumitate` / `nisa_growth` / `taxable`）で課税口座と NISA 口座を区分する。**空欄・列なしの行はすべて課税口座（taxable）扱い**——実際には NISA 保有の銘柄が課税口座として集計されると税価値が過大に出るため、NISA 保有があるのに `account` 列が無い場合は先に列の追加を案内する。
- 任意列 `manual_price` の行（投信・現金の手入力評価）は手入力値で評価される（鮮度の管理はユーザーの責任、レポートに自動注記）。
- `data/portfolio.csv` が無い場合はテンプレート `analysis/templates/portfolio-example.csv` を案内し、ユーザーに保有銘柄を確認してから作成する。勝手に架空の保有内容をでっち上げない。`data/` は gitignore 対象なので保有情報はコミットされない。

### 2. 定量整理 CLI の実行

リポジトリルートから実行する:

```bash
python3 analysis/tax_report.py [--file <パス>] [--period 1y]
```

- `reports/tax-<日付>.md` が生成され、パスが stdout に出力される。内容は (1) 課税口座の銘柄別含み損益と「実現した場合の税価値/課税見込み（試算）」、(2) NISA口座の含み損益（税価値は常に対象外・0円）との対比、(3) 実務上の注意3点（自動挿入）、(4) データと前提。
- **ネットワークが使えない場合**は `--synthetic` を付けて再実行し、最終レポートに「合成データによる手法デモであり、実データではない」ことを必ず明記する。合成データの含み損益・税価値は実際の保有とは無関係である点を強調する。
- CSV のバリデーションエラーは行番号付きで stderr に出る。ユーザーに修正箇所をそのまま伝える。

### 3. ナレッジベースを解釈の枠組みに使う

結果を解釈する前に、必ず以下を読む:

- `knowledge/regulation-tax/taxation-and-nisa.md` — 損益通算（2.2節）・繰越控除（2.3節）・NISAの税制上の性格（4.2節: 損失は税務上「なかったもの」）
- `knowledge/strategies/behavioral-finance-japan.md` — 処分効果（塩漬け）と税務起点の判断の歪み

### 4. 結果の解釈（レポートへの加筆）

CLI が実務上の注意を自動挿入するが、ユーザーへの回答・加筆でも以下の3点を**必ず**添える（省略しない）:

1. **損出しクロスの同日買戻し注意** — 特定口座の取得単価は総平均法に準ずる方法で計算されるため、同一銘柄を同じ日に売却・買付すると取得単価が平均化され、実現できる損失が表の含み損より縮む（2025年時点の実務）。翌営業日以降の買い戻しはこの問題を避けられるが、その間の株価変動リスクを負うトレードオフがある。
2. **繰越控除の申告要件** — 損失の繰越（翌年以降3年）には確定申告が必要で、取引の無い年も申告を継続しないと途切れる。源泉徴収あり特定口座でも複数の証券会社にまたがる損益通算・繰越控除には申告が要る。申告が配偶者控除・国民健康保険料等に影響しうる実務上の論点にも触れる。
3. **tax tail wagging the dog（行動バイアス注意）** — 税価値は売却に付随する二次的な結果であって目的ではない。保有継続の判断はまず「今この価格で新規に買うか」（ゼロベース・テスト）で行い、税務はその後に考える。含み損の放置（処分効果）も税価値だけを理由にした機械的な売却も、どちらもバイアスの現れになりうる。

さらに、以下の読み方を添える:

- **税価値は条件付きの上限の目安** — 同一年内の実現益・申告分離課税を選択した配当等との損益通算、または繰越控除の期間内に相殺できる利益があって初めて生じる。通算相手が無ければ税価値はゼロ。
- **NISAの非対称性** — NISA口座の含み損は損益通算・繰越控除の対象外（税務メリットゼロ）。レポートの対比（「同じ含み損が課税口座にあれば〜円相当」）を、口座区分の使い方を考える材料として提示する。

### 5. 判断の禁止（このスキルの一線）

- **「どの銘柄を売る（損出しする）べきか」「いつ売るべきか」の判断・推奨・優先順位付けは絶対にしない。** 含み損の大きい順の並び替え等、機械的な整列はレポートの表がすでに担う。それを「候補リスト」として提示し直すことも助言化にあたるのでしない。
- 年末（受渡日ベースの年内最終売買日）などの期限に関する一般的な制度情報は事実として伝えてよいが、「それまでに売却を」とは書かない。
- 実際の税額は年間の取引全体・課税方式の選択・他社口座の損益・繰越損失の有無で変わる。最終的な税務の確認は税理士・国税庁の情報によるべきことを添える。

### 6. 免責と品質ゲート

- レポート末尾に免責文が残っていることを確認する（CLI が `stocklib.report.DISCLAIMER` を自動付与。加筆後も残す）。
- この整理を実際の損出し・確定申告の判断に使う前は `/review-report` を通すよう促す。

## 品質の基準

- 含み損益・税価値の数値はすべて CLI の出力に基づく。手で再計算した値を混ぜない。
- 税率（20.315%）・制度（繰越3年・NISA仕様）には「〜年時点」を付記する。
- 「実現した場合の」という条件付き表現を外さない（確定した節税額のように書かない）。
- 評価は直近終値ベースであり、リアルタイムの時価ではないことを明記する。

# デイリーブリーフ

引数（あればウォッチリスト CSV のパス）: $ARGUMENTS

ウォッチリスト銘柄の定点観測と市況サマリーを1本のブリーフにまとめる。**事実（数値・検出シグナル）と解釈（背景・文脈）を分離して書く**。シグナルは機械的な条件検出であり、売買の推奨ではない。

## 手順

### 1. CLI の実行

リポジトリルートから実行する:

```bash
python3 analysis/daily_brief.py                                   # 既定: data/watchlist.csv
python3 analysis/daily_brief.py --watchlist <引数のパス>          # 引数があれば
```

- レポートは `reports/brief-<日付>.md` に保存され、パスが stdout 末尾に出る。
- **ウォッチリストが無い場合**、CLI は `analysis/templates/watchlist-example.csv` を案内して市況のみで続行する。その場合はユーザーに「テンプレートを `data/watchlist.csv` にコピーして銘柄を登録すれば銘柄監視も含められる」ことを伝える（`data/` は git 管理外なので個人のリストはコミットされない）。
- **yfinance への接続に失敗した場合**は `--synthetic` を付けて再実行し、レポートと会話の両方で「合成データによる手法デモであり実データではない」ことを必ず明記する。

### 2. シグナルの解釈

検出されたシグナルを解釈する前に、必ず以下を読む:

- `knowledge/technical/indicators-and-ichimoku.md` — RSI の過熱水準（30/70）と移動平均クロス（ゴールデンクロス・デッドクロス）の意味・ダマシの注意点
- `knowledge/technical/volume-and-market-internals.md` — 出来高急増の読み方（価格変動を伴うか、材料の有無で意味が変わる）

解釈の書き方:

- シグナルの定義・閾値（RSI(14) 30以下/70以上、25/75日線クロス5営業日以内、出来高20日平均比2倍超、52週高値/安値から3%以内、前日比±3%超）は `analysis/stocklib/signals.py` の docstring が正。数値に言及するときはこの定義を引く。
- 複数シグナルが同一銘柄で重なった場合（例: 出来高急増＋急変動）は、単独シグナルより注目度が高い旨を指摘してよい。ただし「上がる/下がる」という断定的な将来予測は書かない。「〜と整合的」「〜の可能性がある」の表現を使う。
- 市況（指数・為替）とウォッチ銘柄の動きが連動しているか（地合いによる動きか、個別材料らしい動きか）を1〜2行で添える。

### 3. 深掘りの提案

シグナルが集中した銘柄・急変動した銘柄があれば、`/analyze <コード>`（analyze-stock スキル）での深掘り分析を提案する。このスキル内では個別銘柄の深掘りはしない。市場全体の詳しい文脈が必要なら `/market`（market-review スキル）を案内する。

### 4. 毎朝の自動実行の案内（求められた場合）

ユーザーが「毎朝自動で」と望んだら、方法の**紹介にとどめる**（具体的な設定はユーザーの環境に依存するため、勝手にスケジュール登録しない）:

- Claude Code の Routine（スケジュールトリガー）で「毎営業日の朝に /brief を実行する」よう設定できる環境がある。
- OS 側では cron（例: 平日朝に `python3 analysis/daily_brief.py` を実行し、出力を確認する）でも定期実行できる。
- いずれの場合も、データ取得元（yfinance）の遅延や休場日がある点、レポートは投資助言ではない点を添える。

## 注意事項

- レポートには免責文が必須（CLI が `stocklib.report.DISCLAIMER` を自動追記する。会話でも投資助言ではない旨を保つ）。
- 完成したらレポートのパスを提示し、シグナルが出た銘柄の要点（銘柄・シグナル種別・一言解釈）を会話でも箇条書きで伝える。

# 実運用パフォーマンス測定（金額加重リターン XIRR）

対象ファイル: $ARGUMENTS

取引履歴 CSV から「入出金のタイミングまで調整した、自分の実績は年率何%だったのか」（金額加重リターン MWR = XIRR）と、「同じキャッシュフローをベンチマークに投じていたらどうだったか」を測定し、実績を運・地合いと切り分けて読むための材料を提供するレポートを作成する。

## 手順

### 1. 取引履歴 CSV の準備

- 引数でパスが指定されていればそれを、省略時は `data/transactions.csv` を使う。無ければテンプレートからコピーして作るよう案内する:

```bash
cp analysis/templates/transactions-example.csv data/transactions.csv
```

- 列は `date,code,side,shares,price,fee,account,memo`（fee・account・memo は省略可）。side は `buy` / `sell` / `dividend` / `deposit` / `withdraw`。
- **dividend 行の書き方**: `shares` に保有株数、`price` に1株配当を入れ、`shares × price` が受取総額になるようにする（総額を直接入れる場合は shares を空欄にして price に総額でもよい）。**配当の源泉徴収税は `fee` に計上する**（受取額から控除される）。テンプレートに記入例がある。
- **fee の意味**: buy は取得原価に算入、sell / dividend は受取額から控除。売買手数料も源泉税もここに入れる。
- **deposit / withdraw 行**（証券口座への入出金）: `code` は空欄、`price` に金額を入れる（shares は空欄で既定 1）。入出金の行が1つでもあると**口座モード**（入出金を外部キャッシュフローとし、現金の遊びも含めた口座全体の実感リターン）、無ければ**ポジションモード**（買付・売却・配当そのものを外部キャッシュフローとみなす。約定履歴だけを記録している人向け）に自動判定される。口座モードを使うなら**入出金の完全な記録が前提**（漏れがあると現金残高が負になり、レポートに警告が出て数値が歪む）。
- ユーザーの取引履歴を勝手にでっち上げない。CSV が無い・不完全な場合は、証券会社の取引履歴・入出金履歴からの転記を案内する。`data/` は gitignore 対象なので取引履歴はコミットされない（git 管理下のディレクトリにコピーしない）。

### 2. 定量測定 CLI の実行

リポジトリルートから実行する:

```bash
python3 analysis/performance_report.py [--file <パス>] [--benchmark ^N225] [--period 3y]
```

- `reports/performance-<日付>.md` が生成され、パスが stdout の最終行に出力される（その前の行に実績 XIRR の要約）。内容は (1) サマリー（投下資金・回収額・終端評価額・総損益）、(2) 損益の内訳（実現・未実現・受取配当・支払手数料）、(3) 実績 XIRR、(4) ベンチマーク比較（同じキャッシュフローを複製した場合の XIRR・終端評価額）、(5) 保有明細と外部キャッシュフロー明細。
- **配当込みの比較をしたい場合は `--benchmark 1306.T`（TOPIX 連動 ETF、分配金調整済み）等を推奨する**。既定の ^N225 は配当を含まない価格指数のため、比較はベンチマーク側が配当の分だけ控えめになる（レポートにも自動で注記される）。
- `--period` 省略時は最初の取引日から必要期間を自動導出する。ベンチマーク系列の開始より古い取引があると系列最初の終値で代用した旨の注記が出る。
- 保有株数を超える売却はエラーになる（買付の記録漏れ・株式分割の未反映をユーザーに確認する）。CSV のバリデーションエラーは行番号付きで stderr に出るので、修正箇所をそのまま伝える。
- **ネットワークが使えない場合**は `--synthetic` を付けて再実行し、最終レポートに「合成データによる手法デモであり、実データではない」ことを必ず明記する。合成データの XIRR・損益は実際の運用成績とは無関係である点を強調する。

### 3. ナレッジベースを解釈の枠組みに使う

結果を解釈する前に、必ず以下を読む:

- `knowledge/math/performance-measurement-and-attribution.md` — 時間加重リターン（TWR）と金額加重リターン（MWR = XIRR）の使い分け、ベンチマーク選択の論点、スキルと運を区別する統計的検定（$t \approx IR \times \sqrt{\text{年数}}$）

### 4. 結果の解釈（レポートへの加筆）

生成されたレポートを土台に、以下を必ず添える:

1. **XIRR は金額加重（MWR）である** — 「いつ・いくら入金したか」という入金タイミングの巧拙まで含んだ、投資家個人の損益実感に対応する数値。運用対象そのものの成績を測る時間加重リターン（TWR）とは別物であり、**指数の公表リターンや投信の基準価額リターン（いずれも時間加重）と実績 XIRR を直接並べて優劣を語るのは不適切**。本レポートのベンチマーク比較が「同じキャッシュフローをベンチマークに投じた場合の XIRR」という複製方式なのは、この非対称を避けるためである。
2. **XIRR の差は優劣の断定ではない** — 実績 − ベンチマーク複製の差（ポイント）は、市場要因（市場全体に乗っていただけの部分）と銘柄選択・タイミングの寄与を分離するための材料であり、差の符号だけで巧拙は判定できない。
3. **計測期間1年未満の年率換算は誇張される** — 年率化は外挿であり、レポートにも自動で注意が付く。短期間の XIRR の絶対値を強調しない。
4. **モードの意味** — 口座モードは現金の遊びも含む「口座全体の実感」、ポジションモードは投下した資金に対するリターン。どちらで測定されたかをユーザーに伝える。
5. **データ品質** — 価格は yfinance（非公式 API）で、日本株では分割・配当調整の不備がありうる。保有明細の現在値・未実現損益が既知の値と明らかに違えばデータ品質を疑う（`knowledge/data-sources/data-apis-and-tools.md`）。

### 5. 「実績が良い＝腕が良い」への短絡に注意（必須）

好成績でも不成績でも、以下を必ず添える:

- 数年程度の実績は、統計的には**運とスキルを区別できない長さ**である（`performance-measurement-and-attribution.md` 第5節: 情報比率 0.5 の運用者がスキルを 5% 水準で立証するには約 16 年を要する）。強い地合いの期間に投資していれば、銘柄選択にかかわらず XIRR は高く出る。
- ベンチマーク比較はまさにこの「地合いの寄与」を切り分けるための材料であり、それでも残る差が運か腕かは短期間では判定できない。好成績の後にリスクを増やす・不成績の後に投げ出す、という反応こそが典型的な行動バイアスである（`knowledge/strategies/behavioral-finance-japan.md`）。

### 6. asset-planning との接続（想定リターンの現実チェック）

実績 XIRR は、asset-planning スキルの「想定リターンの根拠を問い直す」ループの**現実チェック材料**として使える:

- 年1回など定期的に実績 XIRR を測定し、`/plan`（`asset_plan.py progress`）で置いた想定リターンと乖離していないかを突き合わせる。この定点観測が、想定リターンを希望的観測から守る規律になる。
- ただし、**実績 XIRR を asset_plan の `--return`（想定リターン）にそのまま入力しないこと**。実績リターンは (1) 観測期間が短いほど運の寄与が大きい、(2) 入金タイミング要因を含む、(3) 好成績の後には平均回帰が起きうる——ため、将来の期待リターンの推定値としては上下どちらにも偏りうる。想定リターンは市場インデックスの長期期待リターンを軸に保守的に置くのが本環境の推奨（`knowledge/strategies/long-term-wealth-building.md`）。

### 7. 助言化の禁止

- 「勝っていた/負けていた」という優劣の断定、実績を根拠にした売買・戦略変更の指示は書かない。数値と比較材料の提示に徹する。
- 事実（測定値）・解釈（MWR/TWR の違い・地合いの寄与）・不確実性（期間の短さ・データ品質）を区別して書く。

### 8. 免責と品質ゲート

- レポート末尾に免責文が残っていることを確認する（CLI が `stocklib.report.DISCLAIMER` を自動付与。加筆後も残す）。
- 実績を資産計画の見直しなど重要な判断に使う前は `/review-report` を通すよう促す。

## 品質の基準

- XIRR・損益・比較の数値はすべて CLI の出力に基づく。手で再計算した値を混ぜない。
- 計測期間（年数）を必ず添えて XIRR を提示する（期間なしの年率だけを見せない）。
- 「実績リターンは将来のリターンを保証しない」を必ず残す。

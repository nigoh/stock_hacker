# 配当インカム分析

対象ファイル: $ARGUMENTS

保有銘柄 CSV から年間受取配当見込み（直近12ヶ月の実績＝TTMベース）・YOC・時価利回り・税引後の手取り・NISA非課税メリットを集計し、配当インカム投資のナレッジで解釈したレポートを作成する。

## 手順

### 1. ポートフォリオ CSV の確認

- 引数でパスが指定されていればそれを、省略時は `data/portfolio.csv` を使う。列形式は portfolio-review スキルと同一（`code,shares,avg_cost,acquired_date,memo,fx_at_cost,account,target_weight,manual_price`。code と shares と avg_cost 以外は省略可）。
- 任意列 `account`（`nisa_tsumitate` / `nisa_growth` / `taxable`。空欄・列なしは taxable 扱い）があると、NISA口座分は非課税・課税口座分は源泉徴収 20.315%（2025年時点）として手取りが計算され、NISA分の非課税メリット（年間フロー）が試算される。ユーザーが NISA の非課税メリットを知りたがっているのに `account` 列が無い場合は、列の追加を案内する（無くても円建て集計は動く）。
- 任意列 `manual_price` を持つ行（投資信託・現金などの手入力評価行）は配当集計の対象外・年間配当 0 として扱われる。投信の分配金・現金の利息は対象外である旨がレポートに自動で脚注される——ユーザーが投信の分配金を期待している場合はこの限界を先に伝える。
- `data/portfolio.csv` が無い場合はテンプレート `analysis/templates/portfolio-example.csv` を案内し、ユーザーに保有銘柄を確認してから作成する。勝手に架空の保有内容をでっち上げない。`data/` は gitignore 対象なので保有情報はコミットされない（保有 CSV を git 管理下のディレクトリにコピーしない）。

### 2. 定量集計 CLI の実行

リポジトリルートから実行する:

```bash
python3 analysis/income_report.py [--file <パス>] [--period 1y]
```

- `reports/income-<日付>.md` が生成され、パスが stdout に出力される。内容は (1) 銘柄別の1株配当（TTM実績）・年間配当・YOC・時価利回り・口座区分・税引後手取り、(2) 税引後の年間インカム合計と月割り額、(3) NISA分の非課税メリット試算、(4) 前提と限界。
- **ネットワークが使えない場合**は `--synthetic` を付けて再実行し、最終レポートに「合成データによる手法デモであり、実データではない」ことを必ず明記する。合成データの配当額・利回りは実際の保有とは無関係である点を強調する。
- CSV のバリデーションエラーは行番号付きで stderr に出る。ユーザーに修正箇所をそのまま伝える。

### 3. ナレッジベースを解釈の枠組みに使う

結果を解釈する前に、必ず以下を読む:

- `knowledge/strategies/dividend-income-investing.md` — 高利回りの罠・配当性向と増配余力・YOC の使い方と批判・権利落ちの期待値・トータルリターンでの評価
- `knowledge/regulation-tax/taxation-and-nisa.md` — 配当課税の基本構造・課税方式の選択（3節）・新NISA の制度設計（4節）

### 4. 結果の解釈（レポートへの加筆）

生成されたレポートを土台に、以下を必ず添える:

1. **TTM実績と会社予想の違い** — レポートの1株配当は直近12ヶ月に**支払われた実績**の合計であり、会社予想（forward）配当ではない。日本の実務では決算短信の予想配当で見るのが標準的なため、金額が大きい判断の前に会社開示と突き合わせるよう案内する。増配・減配の発表があった銘柄では TTM と予想が大きくずれる。
2. **高利回りの罠** — 時価利回りが突出して高い銘柄（目安: 市場平均の2倍超）は、市場が減配・業績悪化を織り込んで株価を下げた結果である可能性を指摘する（`dividend-income-investing.md` 1節）。利回りの高さを購入理由として推奨しない。可能なら配当性向・業績トレンド（→ `/earnings`）の確認を促す。
3. **株式数比例配分方式の確認** — NISA口座保有株の配当が非課税になるのは、配当受取方式に**株式数比例配分方式**（証券口座での受取）を選択している場合のみ（2024年制度）。銀行振込・配当金領収証方式では NISA 分でも課税される。レポートに自動で注記されるが、ユーザーへの回答でも証券会社の口座設定確認を必ず促す。
4. **データ品質** — 配当データは yfinance（非公式 API）で日本株では欠損・調整不備がありうる。表の1株配当が既知の値と明らかに違う銘柄があれば、データ品質を疑い会社開示との突き合わせを促す（`knowledge/data-sources/data-apis-and-tools.md`）。
5. **月割り額の読み方** — 月割りは単純均等割りであり、実際の入金は権利確定月（3月・9月集中）から2〜3ヶ月後に偏る。生活費への充当を考えているユーザーにはキャッシュフローの偏りを伝える。

### 5. 助言化の禁止

- **高配当銘柄の購入推奨・利回りを上げるための銘柄入れ替え指示は絶対に書かない。** 「利回りを高める余地」のような表現も、特定銘柄の売買に結びつけない。
- 配当はトータルリターンの一部にすぎない（配当を受け取っても株価が下がれば資産は減る）ことを、インカム偏重の依頼ほど意識して添える（`dividend-income-investing.md` 7節）。
- 事実（集計値）・解釈（罠・制度の注意）・不確実性（減配リスク・データ品質）を区別して書く。

### 6. 免責と品質ゲート

- レポート末尾に免責文が残っていることを確認する（CLI が `stocklib.report.DISCLAIMER` を自動付与。加筆後も残す）。
- 受取配当額を家計・投資計画の重要な判断に使う前は `/review-report` を通すよう促す。

## 品質の基準

- 配当額・利回り・手取りの数値はすべて CLI の出力に基づく。手で再計算した値を混ぜない。
- 税率（20.315%）・NISA 制度などの具体値には「〜年時点」を付記する。
- 「実績配当は将来の配当を保証しない（減配リスク）」を必ず残す。

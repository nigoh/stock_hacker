# 資産形成プランニング（積立・逆算・取り崩し・新NISA）

対象: $ARGUMENTS

積立シミュレーション（project）・目標額からの逆算（goal）・目標への進捗確認（progress）・取り崩し（decumulate）を `analysis/asset_plan.py` で試算し、ファンチャート付きレポートを作成する。**出力はユーザー入力の想定リターンに基づく試算であり、将来の予測でも保証でもない**——この位置づけを最初から最後まで崩さない。

## 手順

### 1. 前提の聞き取り

依頼文から読み取れないパラメータは推測ででっち上げず、ユーザーに確認する:

- **どの試算か**: 積立の将来額（→ project）/ 目標額から毎月額の逆算（→ goal）/ **既に運用中で「現在の資産と積立ペースで目標に届くのか」の確認（→ progress）**/ 資産の取り崩し（→ decumulate）
- **金額と期間**: 毎月の積立額（または目標額・取り崩し開始資産と月次引出額/引出率）、年数、初期資産。progress では**現在の資産評価額**（`--current`）も必要——`data/portfolio.csv` がある場合は `portfolio_review.py` の評価額合計を確認して手で渡してよい（自動連携はせず、預貯金・投信など株式以外の資産を含めるかをユーザーに確認する）
- **コスト**（任意、全サブコマンド共通）: 信託報酬・実質コスト（年率%）。`--cost 0.2` のように指定すると想定リターンから控除して計算し、前提表に控除後リターンが明記される。低コストインデックス（0.1%前後）とアクティブ型（1%超）で長期の最終資産が大きく変わる（差1.4%は30年で約34%、`knowledge/market-structure/investment-trusts-and-asset-management.md` 参照、2020年代時点の水準感）ので、投信で運用している場合は入力を促す
- **想定リターンとボラティリティ**（年率%）: ユーザーが自分で置く仮定であることを明確に伝える。参考の枠組みは `knowledge/strategies/long-term-wealth-building.md`（長期の資産形成とリターン前提の置き方）と `knowledge/strategies/household-risk-capacity-and-allocation.md`（家計のリスク許容度と資産配分）を参照。**「過去の平均リターン」をそのまま将来に外挿する危うさ**を一言添える
- **インフレ率**（任意）: 実質価値（現在の購買力）での表示を望むか
- **NISA**（project のみ任意）: 新NISA（2024年開始）の非課税メリット比較を併記するか

ボラティリティの目安を聞かれたら: 株式インデックスはおおむね年率15〜20%程度、債券混合ならより低い（いずれも過去実績ベースの目安、2025年時点）。断定せず「前提として何%を置くか」の判断材料として示す。

### 2. CLI の実行

リポジトリルートから実行する（ネットワーク不要。率はすべて**%表記**）:

```bash
# 積立予測（--nisa で新NISA非課税メリット併記、--inflation で実質価値併記）
python3 analysis/asset_plan.py project --monthly 50000 --years 20 --return 5 --vol 15 [--initial 1000000] [--inflation 1] [--nisa]

# 目標額からの逆算（--vol を付けると達成確率と感応度も出る）
python3 analysis/asset_plan.py goal --target 30000000 --years 25 --return 4 [--vol 15] [--initial 1000000]

# 目標への進捗確認（現在資産+積立ペース → 要求リターン逆算と到達確率。--current は現在の評価額）
python3 analysis/asset_plan.py progress --target 30000000 --years 15 --current 8000000 --monthly 70000 --return 4 [--vol 15] [--cost 0.2]

# 取り崩し（--monthly = 定額 / --rate = 定率、どちらか一方。--inflation-linked で実質一定の引出）
python3 analysis/asset_plan.py decumulate --initial 30000000 --years 30 --return 3 --vol 12 --monthly 120000 [--inflation 1] [--inflation-linked]
python3 analysis/asset_plan.py decumulate --initial 30000000 --years 30 --return 3 --vol 12 --rate 4
```

- `reports/plan-<サブコマンド>-<日付>.md` が生成され、パスが stdout の最終行に出力される。ファンチャート PNG は `reports/img/` に出力されレポートに埋め込まれる。
- モンテカルロはシード固定（既定 42）で再現可能。前提を変えた比較は `--seed` を同じにして実行する。
- `--cost <年率%>` は全サブコマンド共通。信託報酬等を想定リターンから控除（実効リターン $(1+R)(1-c)-1$）して計算する。progress ではコスト控除前に必要なグロスリターンも併記される。

### 3. 結果の解釈（レポートを土台に説明する）

1. **ファンチャートの読み方** — 帯（P5–P95 / P25–P75）は「想定ボラの下でありうる幅」。中央値（P50）が決定論的複利（破線）を下回るのはボラティリティ・ドラッグによる仕様であり、バグではない
2. **元本割れ確率 / 枯渇確率** — 「◯%の確率で〜」はモンテカルロ推定值で、モデル（対数正規・独立同分布）の限界（ファットテール・レジーム変化を過小評価）を必ず併記する
3. **progress の場合** — 「要求年率リターン（目標達成に必要なリターンの逆算値）」と「ユーザー想定リターン」の差が主役。要求リターンが歴史的な株式リターンの参考値（世界株の実質年率約5%・幾何平均、1900年以降、2024年時点。`knowledge/strategies/long-term-wealth-building.md`）を大きく超える場合、レポートに「積立額または期間の見直しの検討材料」という中立的な注記が付く——**「達成できない」と断定せず**、積立額・期間・目標額・リスクのどれを調整するかのトレードオフとして提示する。逆に要求リターンが低い（〜0%以下）場合も「余裕がある」と楽観させず、積立継続が前提であることを添える
4. **取り崩しの場合** — シークエンス・オブ・リターンズ（序盤の下落が致命的になる非対称性）と、定率方式は「枯渇しない代わりに受取額が減る」トレードオフを説明する
5. **NISA の場合** — 非課税メリットは「課税口座なら払っていた税額（20.315%、2025年時点）」。損失時は損益通算不可の非対称があること、つみたて投資枠年120万円・成長投資枠年240万円・生涯1,800万円の枠（2025年時点）との関係を確認する
6. **家計との整合** — 必要積立額・引出額が家計として持続可能か、リスク許容度（`knowledge/strategies/household-risk-capacity-and-allocation.md`）と整合するかを観点として示す

### 4. 想定リターンの根拠を問い直す（必須）

レポートを渡す際に、必ず次の注意喚起を行う:

- **「その想定リターンの根拠は何か？」** を問い直す。過去平均の外挿・SNSやセールス資料の数字・都合のよい期間の切り取りは、計画全体を楽観に歪める
- 感応度を示す: goal では想定リターン±1〜2ポイントの必要積立額の変化がレポートに含まれる。project / decumulate でも、求められれば `--return` を変えて再実行し幅を見せる
- **前提を1〜2ポイント厳しくしても破綻しない計画か**を確認の観点として提示する

### 5. してはいけないこと

- 特定の商品・銘柄の購入指示（「〜を買えば達成できる」）は書かない。想定リターンを特定商品の期待リターンとして断定しない
- 「この確率なら大丈夫」という安全宣言をしない。確率はモデルの仮定の産物である
- 免責文はCLIが自動付与するが、加筆後も残っていることを確認する。重要な判断（退職・大きな資産移動など）に使う前は `/review-report` を通すよう促す

## 品質の基準

- 数値はすべて CLI の出力に基づく。手計算の値を混ぜない
- 税率・NISA枠などの制度数値には「〜年時点」を付記する（制度は変わる）
- 事実（計算結果）・仮定（ユーザー入力）・限界（モデルの単純化）を明確に区別して書く

# 決算・業績分析（時系列深掘り）

対象銘柄: $ARGUMENTS

日本株1銘柄の業績（売上高・営業利益・純利益・自己資本・営業CF）の時系列を分析し、成長性・収益性の推移を評価するレポートを作成する。

## /analyze との使い分け

- **業績の時系列深掘り（決算数値の推移・成長の質）はこのスキル**。株価・テクニカル・リスク指標は扱わない。
- 株価水準・バリュエーション・テクニカルを含む**総合分析は analyze-stock（/analyze）**。総合分析の中でファンダ面を深掘りしたくなった場合に、このスキルを追加で使うのが典型的な流れ。

## 手順

### 1. 銘柄の特定

引数から4桁の銘柄コードを確認する（例: `7203`）。社名で指定された場合は `analysis/universe/liquid30.csv` を参照、無ければ WebSearch で「<社名> 証券コード」を検索してコードに変換する。

### 2. 業績レポートの生成

リポジトリルートから実行する:

```bash
python3 analysis/fundamentals_report.py <code> --years 5
```

- 成功すると `reports/fundamentals-<code>-<日付>.md` が生成され、パスが stdout に出る。業績推移テーブル（百万円）、売上/営業利益/純利益の CAGR、連続増収・増益期数、営業利益率・純利益率・ROE の年次推移が含まれる。
- 数値ソースは yfinance（`income_stmt` / `balance_sheet` / `cashflow`）。取得できる期数は通常4〜5期に限られる。
- **ネットワークが使えない・取得に失敗する場合**は `--synthetic` を付けて再実行する。このとき最終レポートに「合成データによる手法デモであり実データではない」ことを必ず明記する（CLI 出力にも明記される）。

### 3. ナレッジベースで解釈の枠組みを作る

分析・執筆の前に必ず以下を読む:

- `knowledge/fundamental/reading-japanese-financials.md` — 決算短信と有価証券報告書の違い、日本基準/IFRSの段階損益の差、財務諸表の読み方
- `knowledge/fundamental/earnings-guidance-and-consensus.md` — 会社予想（ガイダンス）の慣行と保守性。**本 CLI の出力は実績のみで会社予想を含まない**ため、予想対比の議論はこの文書を枠組みに WebSearch 等で補足する
- `knowledge/fundamental/valuation-metrics.md` — ROE・マージンの水準感、デュポン分解、PBR ≒ ROE×PER の関係

解釈の要点:

- CAGR は始点・終点依存が強い。始点が異常年（コロナ期の赤字等）でないかを推移テーブルで確認する。赤字を跨ぐ CAGR は計算されない（`-` 表示）仕様。
- マージンの改善/悪化は増収効果（オペレーティングレバレッジ）か構造変化かを区別して書く。
- ROE の変化はデュポン分解（利益率×回転率×レバレッジ）の視点でどの要因かを推定する。自己資本の急増（増資）・急減（自社株買い）にも注意。
- 営業CF と純利益の乖離（アクルーアル）は利益の質のシグナルとして言及する。

### 4. EDINET 原文確認（APIキーがある場合）

環境変数 `EDINET_API_KEY` が設定されていれば、手順2のレポートに直近の有価証券報告書・半期報告書の一覧（docID 付き）が自動で載る。より深く確認する場合:

```bash
PYTHONPATH=analysis python3 -c "
from stocklib.edinet import fetch_document_csv
df = fetch_document_csv('<docID>')  # 財務諸表CSV（XBRL項目の縦持ち）
print(df[df['項目名'].str.contains('売上', na=False)].head(20))
"
```

- 有報原文は「事業等のリスク」「MD&A」等の定性情報の宝庫。数値の裏取りと定性補足に使う。
- **数値系列は yfinance を正とする**（EDINET の XBRL は会計基準・タクソノミ差で銘柄横断の機械処理が難しい。設計判断は `stocklib/fundamentals.py` の docstring 参照）。両者が食い違う場合はレポートに差異として明記する。
- キー未設定なら無理に取得しない（レポートに導線が自動で載る）。**決算短信（適時開示・TDnet）は EDINET では取れない**ので、短信ベースの速報値が必要なら WebSearch で補足する。

### 5. 統合レポートの完成

手順2の生成物を土台に加筆・再構成し、以下の章立てで完成させる:

1. **サマリー** — 成長性・収益性の評価を3〜5行、良い点と懸念を両論併記
2. **業績推移** — テーブル + 傾向の記述（増収増益の連続性、変曲点）
3. **収益性の質** — マージン推移、ROE とその要因、営業CFとの整合
4. **開示情報** — EDINET 書類一覧（あれば）、原文からの補足
5. **限界と注意** — データソース（yfinance）の制約、会社予想を含まないこと、会計基準の差異
6. **免責** — 末尾に必ず入れる（`stocklib.report.DISCLAIMER`。CLI 生成分には自動付与される）

## 品質基準

- 具体的な数値には会計期間（「2025年3月期」等）を必ず付記する。
- 事実（データ）・解釈（分析）・不確実性（わからないこと）を区別し、断定的な将来予測は書かない。
- 合成データ使用時はその旨をサマリーにも明記し、実在企業の業績として解釈しない。
- 外部共有・意思決定に使う前は `/review-report` を通す。

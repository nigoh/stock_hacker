# 銘柄スクリーニング

指定された条件: $ARGUMENTS

条件に合致する日本株をユニバースから抽出し、結果を「仮説の候補リスト」として解釈・報告する。スクリーニングは結論を出す道具ではなく、深掘りすべき銘柄を絞り込む道具である。

## 手順

### 1. 条件の聞き取りと解釈

ユーザーの条件を定量的なフィルタに翻訳する。曖昧な場合は確認するか、解釈を明示した上でデフォルトを使う:

| ユーザーの表現 | 解釈の例 | CLI オプション |
|---|---|---|
| 「売られすぎ」「反発しそう」 | RSI(14) が 30 未満 | `--rsi-below 30` |
| 「買われすぎ」「過熱している」 | RSI(14) が 70 超 | `--rsi-above 70` |
| 「上昇トレンド」「長期線の上」 | 終値 > SMA200（または SMA75/25） | `--price-above-sma 200` |
| 「下降トレンド」「長期線の下」 | 終値 < SMA200（または SMA75/25） | `--price-below-sma 200` |
| 「出来高が増えている」「出来高急増」 | 直近出来高が過去20日平均の2倍以上 | `--volume-surge 2.0` |
| 「急落した」「大きく下げた」 | 期間リターンが −10% 未満 | `--return-below -10` |
| 「急騰した」「勢いがある」 | 期間リターンが +10% 超 | `--return-above 10` |
| 「割安」 | PER（実績）が 15 未満・PBR が 1.0 未満 | `--per-below 15` / `--pbr-below 1.0` |
| 「高配当」「配当が厚い」 | 配当利回りが 3% 超 | `--dividend-yield-above 3.0` |

- 解釈を勝手に決めた場合は、レポートと返答の両方で「この条件をこう解釈した」と明示する。
- 条件の意味づけに迷ったら先に knowledge を読む:
  - `knowledge/technical/indicators-and-ichimoku.md` — RSI・移動平均の定義と限界（RSI30割れは下降トレンド中に張り付くことがある、等）
  - `knowledge/technical/volume-and-market-internals.md` — 出来高条件の読み方
  - `knowledge/fundamental/valuation-metrics.md` — PER/PBR 条件の落とし穴（低PBRは低ROEの裏返しであることが多い）

### 2. スクリーニングの実行

リポジトリルートから実行する:

```bash
python3 analysis/screen.py --rsi-below 30 --price-above-sma 200
```

- 主なオプション:
  - `--universe analysis/universe/liquid30.csv`（デフォルト）、`--period <期間>`（既定 1y）、`--synthetic`
  - `--rsi-below <値>` / `--rsi-above <値>` — RSI(14) の売られすぎ / 買われすぎ
  - `--price-above-sma <期間>` / `--price-below-sma <期間>` — 終値と SMA(N) の上抜け / 下抜け（トレンド判定）
  - `--volume-surge <倍率>` — 直近出来高が過去20日平均の指定倍率以上（出来高急増）
  - `--return-below <％>` / `--return-above <％>` — 取得期間全体のリターン閾値（例: `--return-below -10` は期間リターン −10% 未満）
  - `--per-below <値>` — PER（実績）が指定値未満（割安。例: 15）。値が取得できない銘柄は除外
  - `--pbr-below <値>` — PBR が指定値未満（割安。例: 1.0）。値が取得できない銘柄は除外
  - `--dividend-yield-above <％>` — 配当利回りが指定値（%）超（高配当。例: 3.0）。値が取得できない銘柄は除外
  - 複数指定は AND 条件。最新のオプション一覧は `python3 analysis/screen.py --help` で確認してから条件をマッピングする。
- 結果テーブルが stdout に出力され、`reports/screen-<日付>.md` にも保存される。
- **ネットワークが使えない場合**は `--synthetic` を付けて再実行し、レポートに「合成データによるデモであり、実データではない」ことを必ず明記する。
- バリュエーション条件（`--per-below` / `--pbr-below` / `--dividend-yield-above`）に関する注意:
  - **実データ時は時間がかかる**: バリュエーション取得のため銘柄ごとに yfinance の info 取得（`Ticker("<code>.T").info` 相当）が追加で走る。liquid30 でも体感で遅くなり、大きなユニバースでは顕著。ユーザーに所要時間の見込みを一言添える。
  - **`--synthetic` 時はダミー値**: PER/PBR/配当利回りはシード固定の合成ダミー値であり、実在の企業指標ではない。screen.py もレポートにその旨を自動で書き出すが、最終レポート・返答でも必ず明記し、実データと誤認させない。
- CLI 未対応の条件のみ（例: ROE・時価総額・自己資本比率など）、screen.py の結果に対して yfinance（`Ticker("<code>.T").info`）で追加取得して手元で絞り込むか、対応不可であることを明示する。推測でフィルタしない。

### 3. ユニバースの限界を必ず明示する

- デフォルトユニバース `analysis/universe/liquid30.csv` は**主要流動30銘柄のサンプル**（2025年時点）にすぎない。東証全上場銘柄（約3,900銘柄）のスクリーニングではない。
- 「該当なし」は「市場全体に該当銘柄がない」ことを意味しない。この点を結果報告に必ず書く。
- 全銘柄スクリーニングには J-Quants API 等のデータソースが必要。本リポジトリには接続モジュール `stocklib.jquants` が実装済みで、環境変数 `JQUANTS_REFRESH_TOKEN`（https://jpx-jquants.com/ の無料プラン登録で発行）が設定されていれば、次の要領で全銘柄ユニバースの CSV を構築し `--universe` に渡せる:

  ```python
  # リポジトリルートから: PYTHONPATH=analysis python3 で実行
  from stocklib.jquants import fetch_listed_info
  listed = fetch_listed_info()  # 全上場銘柄（Code は5桁形式）
  df = listed.rename(columns={"CompanyName": "name", "Sector33CodeName": "sector"})
  df["code"] = df["Code"].str[:4]  # screen.py 用に4桁化（英字入り5桁コードは除外を検討）
  df[["code", "name", "sector"]].to_csv("analysis/universe/jquants-all.csv", index=False)
  ```

  ```bash
  python3 analysis/screen.py --universe analysis/universe/jquants-all.csv --rsi-below 30
  ```

  価格取得は yfinance 経由のため全銘柄では時間がかかる点、Free プランの銘柄一覧は最新でない可能性がある点をレポートに明記する。トークン未設定なら `JQuantsAuthError` が導入手順を表示するので、それをユーザーに案内する。詳細・注意点（5桁コード・調整系列）は `knowledge/data-sources/data-apis-and-tools.md` の J-Quants 節を参照。

### 4. 結果の解釈 — スクリーニングは仮説生成であり結論ではない

結果を報告する前に `knowledge/math/backtesting-and-statistics.md` を読み、以下の観点を解釈に織り込む:

- **多重検定の罠**: 条件を何通りも試して「効きそうな」組み合わせを見つけても、それは偶然の産物であることが多い（データスヌーピング）。試した条件の数を正直に記録する。
- **ヒット銘柄は「買い候補」ではなく「調査候補」**: RSI30以下は逆張りシグナルではなく「なぜ売られたか」を調べる出発点。悪材料（業績悪化・希薄化・不祥事）で売られた銘柄が混ざる。
- **条件が緩いほどノイズ、厳しいほど偶然**: 30銘柄ユニバースで条件を重ねると該当が0〜数銘柄になり、統計的に何も言えなくなる。
- 有望な銘柄が絞れたら、個別の深掘りは analyze-stock スキル（`python3 analysis/analyze_stock.py <code>`）に引き継ぐ。

### 5. レポートの仕上げ

`reports/screen-<日付>.md`（手順2の生成物）を土台に、以下を含む形に加筆する:

1. **スクリーニング条件** — ユーザーの依頼原文と、それをどう定量条件に翻訳したか
2. **ユニバースと実行日** — liquid30（サンプル30銘柄、2025年時点）である旨と限界
3. **結果テーブル** — code / name / sector / 指標値
4. **解釈** — 各ヒット銘柄の一言コメント（なぜ条件に該当したかの仮説）。事実と解釈を区別する
5. **次のアクション** — 深掘りすべき候補と analyze-stock への導線
6. **免責** — 末尾に必ず入れる（下記）

## 質の基準

- スクリーニング結果を「おすすめ銘柄」として提示しない。常に「条件に合致した調査候補」と表現する。
- 指標の閾値（RSI30、SMA200等）は慣習的な目安であり理論的根拠は弱いことを認識して書く。
- 該当0件も立派な結果。無理に条件を緩めて銘柄をひねり出さない（緩めた場合はその旨を明示する）。
- 具体的な数値・制度には「〜年時点」を付記する。
